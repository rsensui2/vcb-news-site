Akshay — Hermes Agent マスタークラス

概要

Nous Research の OSS エージェント Hermes Agent を全方位解説。2ヶ月で GitHub 90,000 stars。OpenClaw と対比した「ゲートウェイの周りに学習エージェントをパッケージ」する設計。三層メモリ + 自己進化スキル + GEPA オフライン最適化を兼ね備える唯一の OSS。

関連リンク

  • X Article
  • Hermes Agent (NousResearch): GitHub 90k stars

日本語訳全文

セッションが終わると全てを忘れる — 既存 AI エージェント全ての共通課題に、Nous Research の Hermes Agent は根本的に違うアプローチを取る。「セッションを跨いで記憶する」「再利用可能なスキルを自分で書く」「バックグラウンドでそれらを刈り込む」「GEPA という進化的エンジンでオフライン検証する」— この4つを兼ね備える OSS は他にない（OpenClaw も含めて）。

アーキテクチャ概要

  • 全ては run_agent.py の単一 AIAgent クラスに流れる。CLI、メッセージングゲートウェイ、バッチ実行、IDE 連携の全てが同じコアエージェントへの入口
  • コアループは ReAct 様式・同期: システムプロンプト構築 → 圧縮必要か確認 → 中断可能な API 呼出 → ツール実行 → ループ
  • 6種類の実行環境: ローカルターミナル / Docker / SSH / Modal / Daytona / Singularity（config 変更のみで切替）
  • ほぼ全てのモデルで動作。3種の API フォーマットを変換層が吸収
  • 1タスク 90 ターンのハードキャップ（サブエージェントも予算共有）

SOUL.md（アイデンティティ層）

~/.hermes/SOUL.md、システムプロンプト slot #1。人格・トーン・コミュニケーションスタイル・絶対ルールを定義。手書き・静的。後続のメモリやスキル生成はこの SOUL.md のレンズを通して行われる。

メモリシステム — 三層、三速度

  • Tier 1: MEMORY.md (2,200 chars) + USER.md (1,375 chars)。セッション開始時にプロンプト注入。途中で書いたメモは即ディスク永続化されるが、次セッションから初めてプロンプトに現れる。80% 容量で自動統合
  • Tier 2: SQLite + FTS で全会話を保存・全文検索可
  • Tier 3: 8 種類のプラガブル外部メモリプロバイダ（同時1個のみ）。各ターン前にプリフェッチ、各応答後に同期、セッション終了時に抽出

自己進化スキル

YAML frontmatter 付きの Markdown ファイル = 手続き的記憶。Progressive disclosure:

  • Level 0: 名前 + 説明のみ（カタログ全体で ~3k tokens）
  • Level 1: 必要時にスキル本文を読み込み
  • Level 2: 参照ファイルへの drill-in

エージェントは skill_manage ツールで自律的にスキルを作成。トリガー:

  • 複雑なタスクを完了（5+ tool calls）
  • エラー/行き詰まりから動く方法を発見
  • ユーザーに修正された
  • 非自明なワークフローを発見

アクション: create / patch（推奨 — トークン効率良し）/ edit / delete / write_file / remove_file

Curator — スキルの GC

  • 非アクティブ判定: 最終実行から 7日経過 + 2時間以上アイドル → バックグラウンドでフォーク
  • フェーズ1（決定論的・LLM 不使用）: 30日未使用 → stale、90日未使用 → archived
  • フェーズ2（LLM、最大8イテレーション）: フォークされたエージェントがスキル群を調査、keep / patch / consolidate / archive を判断
  • 重要な制約: bundled / hub-installed スキルには絶対触らない（agent 製のみ対象）、自動削除はしない（~/.hermes/skills/.archive/ への移動のみ、ワンコマンドで復旧可能）
  • 全 Curator パス前に tar.gz スナップショット取得 — ロールバックもワンコマンド、ロールバック自体も可逆
  • hermes curator pin <skill> で archive/delete から保護（patch/edit は通る = 改善は受け入れる）

GEPA — 実行トレースを使ったオフラインスキル進化

別リポ NousResearch/hermes-agent-self-evolution、ICLR 2026 Oral 採択、MIT。

弱点に対する対策: 「自分はうまくやった？」と聞くのではなく、実行トレースを読んで「なぜ失敗したか」を理解し、進化的探索で改良案を提案。

パイプライン:

  1. Hermes リポから現在のスキル読み込み
  2. 評価データセット生成（Claude Opus による合成 / SQLite のリアル履歴 / ハンドキュレート）
  3. GEPA オプティマイザ: トレース → 失敗箇所 → 候補生成
  4. LLM-as-judge + ルーブリックで採点（バイナリではなく）
  5. 制約ゲート: 全テスト 100% 合格、スキル 15KB 以下、キャッシュ互換性維持、意味的ドリフトなし
  6. 最良の variant → Hermes リポへの PR として提出（直接 commit はしない）

GPU 不要、API 呼出のみ。1回 $2-10。

セットアップ

  • Linux / macOS / WSL2、Python 3.11+、8GB RAM
  • ワンライナーインストール → hermes setup ウィザード
  • Telegram bot: @BotFather から token、@userinfobot から user ID

~/.hermes/ レイアウト

  • config.yaml — シークレット以外の単一の真実
  • .env — シークレット
  • SOUL.md — slot #1
  • skills/ — 学習ループ全体がここ
  • state.db — SQLite + FTS5

公式 Skills Hub

687 スキル / 18 カテゴリ。87 built-in、79 opt-in、Anthropic から 16（frontend-design, pdf, pptx, docx, mcp-builder 等）、LobeHub から 505。任意の GitHub リポをカスタム tap として追加可。

1人 → 10人の AI エージェント（Profiles）

hermes profile create <name> --clone で完全分離されたインスタンス（config / memory / skills / sessions / SOUL.md）。

各 profile は独自の Telegram bot が必要（Telegram は1 token 1接続まで）。

三人格の例:

  • Designer — 参照デザインを食わせ、「同じスタイルの画像を生成するスキルを書け」と指示。エージェントが SKILL.md と Python スクリプトを書き、~/.hermes/profiles/designer/skills/my-design-style/ に保存。以降は Nano Banana 経由で生成
  • Programmer — 起動プロンプト: 「Claude Max サブスク持っている。staff engineer として、コード実行は Claude Code 経由でやれ」→ 自分で autonomous-ai-agents/claude-code スキルをインストール、以降のコード作業は全部 Claude Code CLI 経由
  • Researcher — 毎日 Telegram に digest 配信、Hermes cron で自動化

Cron は自然言語で

  • ゲートウェイデーモンが 60 秒ごとに tick、~/.hermes/cron/jobs.json に登録、出力は ~/.hermes/cron/output/
  • /cron add 30m "Remind me to check the build" — ワンショット
  • /cron add "every 2h" "Check server status" — 繰返
  • /cron add "0 9 * * 1-5" "..." — 標準 cron 式
  • /cron add "every 1h" "..." --skill blogwatcher — スキル付加
  • ジョブのチェーン: context_from フラグで cron A 出力 → cron B 入力（多段自動化）
