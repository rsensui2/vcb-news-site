本文 (X Article・技術部分抜粋)

タイトル: 【Claude Code】『Opus4.8』を徹底検証した結果「GPT-5.5敗北」

Anthropic が 2026年5月28日に発表した Claude Opus 4.8（Opus 4.7 の後継・上位モデル）の解説。GIGAZINE / ZDNET Japan / Anthropic公式 / System Card をもとに整理。

4つの注目点

  1. ソフトウェア開発・コード修正の性能向上
  2. AIエージェントとして長時間作業を進める能力の強化
  3. 誤った主張・見落としを減らす「誠実さ」の改善
  4. dynamic workflows / effort control / Messages API改善 / fast mode などの新機能

ベンチマーク（公開情報）

  • SWE-Bench Pro: 69.2%（Opus 4.7 = 64.3%、GPT-5.5 = 58.6%、Gemini 3.1 Pro = 54.2% を上回る）
  • Terminal-Bench 2.1: 74.6%（GPT-5.5 = 78.2% に劣後 — ターミナル操作は他社が強い場面あり）
  • Humanity's Last Exam: 49.8% / DRACO: 57.9% / OSWorld-Verified: 83.4% / Finance Agent v2: 53.9%
  • 単純ランキングではなく用途別の判断材料として見るべき。SWE-Bench系が高い＝既存コードの修正・バグ対応で使いやすい。

最大の特徴は「誠実さ」（ZDNET Japan）

分からないことを分からないと言える／根拠のない断言を避ける／自分の作業の欠陥を隠さず報告する性質。System Card では多くのアラインメント指標で改善し、特にエージェント設定での誠実さが大きく向上、欠陥コードを報告しない傾向が大幅低下と説明。業務導入で「間違っているのに自信満々な回答」を避けられる点が重要。

dynamic workflows（Claude Code連携）

Claudeが大きな作業を計画→複数サブエージェントに分解→並列実行→結果を検証してから返す仕組み。数十〜数百の並列サブエージェントを1セッションで動かす。対象: コードベース全体のバグ調査、最適化監査、セキュリティ監査、大規模移行、API置き換え、フレームワーク移行。ただし通常セッションより大幅に多くのトークンを消費するため、範囲を絞って試すべき。

effort control / fast mode / Messages API

  • effort control — どれだけ深く考えさせるかを調整（高=高品質、低=高速・低消費）。Claude.ai / Cowork に追加。
  • fast mode — 2.5倍速。価格は入力$10/出力$50（通常モードは入力$5/出力$25 per 1Mトークン）。速度が売上/顧客体験に直結する業務向け。
  • Messages API — messages配列内に system entries を含められるように。長時間エージェント実行中に権限・トークン予算・環境情報・規約を途中更新しやすくなる（開発者にとって重要）。

注意点

ベンチマークと自社業務の差は実タスクで小さく検証／トークン消費増は範囲限定＆事前見積もり／誤回答は人間レビュー＋根拠確認／プロンプトインジェクション対策（エージェント文脈では Opus 4.7 比でやや堅牢性が落ちる場面ありとSystem Card）／最小権限運用。なお Opus 4.8 は多くの評価で 4.7 を上回るが、Claude Mythos Preview よりは全体的に弱いとされる。

概要

Claude Opus 4.8 の技術解説。SWE-Bench Pro 69.2% で GPT-5.5・Gemini 3.1 Pro を上回る一方、Terminal-Bench では GPT-5.5 に劣後。最大の進化は「誠実さ」（不確実性を示し欠陥を隠さない）と、Claude Code の dynamic workflows（数十〜数百サブエージェントの並列実行＋自己検証）。effort control・fast mode・Messages API の system entries も実務に効く。完全自動化は危険で、小さく検証→人間レビュー→段階展開が推奨。
