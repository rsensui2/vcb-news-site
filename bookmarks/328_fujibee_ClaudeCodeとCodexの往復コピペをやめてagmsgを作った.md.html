Claude Code と Codex の往復コピペをやめたくて、agmsg を作った

094BOOKMARK / 448

有益度: ⭐⭐⭐⭐⭐

エンゲージメント: RT 353 / Likes 3,346 / Bookmarks 6,624 / Views 1,848,849

概要

Claude Code と Codex を 2 台体制で併用する開発で、AI 間のメッセージを人間がコピペで運ぶ「伝書鳩問題」を解消するために作った OSS「agmsg」の紹介記事。CLI の AI エージェント同士が共有 SQLite を介して直接メッセージを送り合える仕組みで、Claude Code / Codex / Gemini CLI などどの CLI エージェントでも使える。Agent Skills ベースで、スキルとして入れるだけ。依存は bash と sqlite3 のみ。

X Article 本文

最近の開発は Claude Code がメインで、そこに Codex を足して2台体制で回している。で、これが思いのほか噛み合う。Claude Code でガリガリ実装を進めて、難しいところやレビューだけ Codex に投げる、みたいな分担に自然と落ち着いた。

……のはいいんだけど、しばらくやってて気づいた。自分、ずっと2つのAIの間でメッセージをコピペして運んでるだけの人になってないか？と。

Claude Code が書いたコードを選択してコピー、Codex のウィンドウに貼ってレビューさせる、返ってきた指摘をまたコピーして Claude Code に戻す。これを一日に何十回もやる。地味なんだけど、これが本当にだるい。集中も切れるし、たまに貼り間違える。要は、賢いAIを2台も並べておいて、その間をつなぐ一番アホな作業を人間がやっていた。

エージェント同士が直接メッセージを送り合えればいいだけの話では？と思って、勢いで作った。agmsg という名前で OSS にしている → https://github.com/fujibee/agmsg

依存は bash と sqlite3 だけ。専用のデーモンやサーバーは立てないし、ネットワークも python も要らない。同じ「チーム」に参加した2つのエージェントは、これだけで互いにメッセージを送れるようになる。「alice にレビュー終わったって送って」「メッセージ来てる？」と自然言語で話しかけるだけ。

設計で考えたこと: まず純正機能（team/subagent）を調べたが short-lived 前提で継続会話に不向き。最初はテキストファイルで実装したが、永続×並行で同時書き込み競合・ファイル破損が問題に。SQLite（WALモード、複数リーダー+1ライター、トランザクション）に切り替えた。ただし依存は最小に保つことに一番こだわった。

受信モード: 手動取得 / hook（Stop フック、Codex 既定）/ monitor（SQLite 常時購読でリアルタイム割り込み、Claude Code 既定）。monitor が入ってから実用性が一気に上がった。monitor 設定済みの Claude Code 同士を同じチームに入れると人間が操作しなくても勝手にやり取りが続く（マルバツゲームを最後まで自律対局させた例）。

一番手こずったのは Claude Code と Codex で hook や設定の仕組みがまるで違うこと。Claude Code には Monitor やリッチな SessionStart 系フックがあるが Codex には無い。受信モードを分けているのもこの差を吸収するため。
