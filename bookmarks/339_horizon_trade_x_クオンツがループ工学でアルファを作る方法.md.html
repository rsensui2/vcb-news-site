概要

ループ工学を クオンツ（定量取引）の因子探索 に応用したフレームワーク解説（自社プラットフォーム Horizon の宣伝を兼ねる）。「バックテストは完璧だったのに本番で溶けた」——それは1回の推測に何も反復していなかったから、という導入。戦略を生成 → 検証 → スコアリング → 失敗理由をフィードバック → out-of-sample で生き残るまで回す、というループの形を、スコアリングの数式まで含めて示す。

まとめ

  • one-shot が止まる理由: 1プロンプト＝1推測。最初のアイデアが edge であることは稀で、ループがないと毎回ゼロから始まり何も蓄積しない。
  • ループを閉じる指標: 情報係数 IC = corr(factorₜ, returnₜ₊₁)。単発は noisy なので、時間的な一貫性 ICIR = mean(IC)/std(IC) を最適化対象にする。地味でも安定した IC が、一度だけ効く派手な因子に勝つ。
  • 多くが飛ばす減衰チェック: 因子の持続性を AR(1) で当てはめ half-life = -ln(2)/ln(ρ) を読む。半減期50日は遅く tradeable、2日ならコストを払ってノイズを追っているだけ。
  • edge と過学習を分ける1ステップ: 同じデータで最適化するループは "綺麗なノイズ" を速く作るだけ。out-of-sample ゲート（見たことのないデータでも ICIR が保つか）だけが研究エンジンに変える。試行回数が増えるほど合格ラインを上げる。
  • 典型的な誤り: in-sample でループする / スコア関数なし / 高 IC だけ見て安定性を無視 / モデルを method と勘違い（良いモデルは生成を速くするだけ、alpha を生むのは loop・scoring・out-of-sample gate）。

日本語訳全文

あなたのバックテストは完璧に見えた。本番投入した。2週間後、戦略は出血していた。どのクオンツも一度はこれを経験している。その答えはループだ。

戦略を生成し、テストし、スコアリングし、結果をフィードバックし、out-of-sample で1つが生き残るまで再び回す。

さっそく本題に入ろう。

これをブックマークしてほしい。私たちは Horizon の開発チームだ。Horizon は、取引戦略を平易な英語でタイプし、数分でバックテストし、自分の取引所へライブでデプロイできるプラットフォームだ。ループ工学（loop engineering）は、そのフローの背後にある手法（method）である。現在クローズドベータ中。horizon.trade で waitlist に参加するか、早期アクセスは @horizon_trade_x まで DM を。

その戦略が死んだのは、何も反復していない1回の推測だったからだ。シングルパスは1回の試行しか与えてくれず、最初の試行が edge であることは稀だ。ループはその1回の試行を「探索（search）」へと変える。各ラウンドでスコアの良かった variant（変種）を残し、残りを次の精緻化へとフィードバックする。これから、そのループがどう機能するか、それを閉じる数式、そして本物の edge と「より速い過学習」とを分ける唯一のステップを分解していく。

Horizon がエンドツーエンドで回す場所

なぜ one-shot プロンプティングは行き詰まるのか

1つのプロンプトは1つの推測しか与えない。モデルは汎用的な factor を返し、あなたはそれをバックテストし、たいてい失敗する。なぜなら最初のアイデアが edge であることは稀だからだ。ループがなければ、すべての試行はゼロから始まり、何も複利的に積み上がらない。edge のすべては反復（iteration）の中にあり、one-shot プロンプティングにはそれがまったくない。

ループ工学とは実際には何か

ループ工学とは閉じたサイクルだ。仮説を生成し、テストし、明確な目的に対してスコアリングし、なぜ失敗したかを読み取り、それを次の生成へとフィードバックする。その形は「知覚する、推論する、行動する、観測する、繰り返す（perceive, reason, act, observe, repeat）」だ。各パスは安価で、システムは鋭くなっていく。なぜなら、どの結果も探索を絞り込んでいくからだ。重要なのはプロセスである。なぜならそれは、数十回の凡庸な試行を、持ちこたえる1つへと変えるからだ。これが、私たちが Horizon をエンドツーエンドで回すために作ったループだ。

ループを閉じる指標

スコア関数のないループは、ただ彷徨うだけだ。因子研究における標準的な目的関数は情報係数（information coefficient）だ。これは、今日の factor の値と、その後に続くリターンとの相関である。IC = corr(factorₜ, returnₜ₊₁)。単発の IC の読みは noisy なので、実際に重要なのは時間を通じたその一貫性、すなわち ICIR だ。ICIR = mean(IC) / std(IC)。控えめでも安定した IC を持つ factor は、一度だけ効いて壊れる派手なものに勝る。ICIR こそ、ループが最適化していく対象だ。

多くの人が飛ばす減衰チェック

本物の factor でさえ賞味期限がある。それは測定できる。シグナルの持続性を AR(1) プロセスとして当てはめ、その half-life を読む。t½ = -ln(2) / ln(ρ)。ここで ρ は、factor がある期間から次の期間へどれだけ強く引き継がれるかだ。half-life が50日なら、それは遅く、tradeable な edge だ。half-life が2日なら、あなたはコストを払ってノイズを追っているだけだ。良いループは short-half-life の factor を自動的に棄却する。

edge と過学習を分けるステップ

ここが、誇大宣伝が飛ばす部分だ。構築に使ったのと同じデータ上で最適化するループは、alpha をより速く見つけるのではない。より綺麗なノイズをより速く見つけるのだ。追加の iteration はすべて、過去にフィットさせるもう1つの機会にすぎない。ループを研究エンジンへと変える唯一のものは out-of-sample ゲートだ。生き残った各候補は、それが一度も見たことのないデータ上でテストされ、そこでも ICIR が保たれなければならない。試行回数は正直に数えること。なぜなら試す variant が多いほど、合格ラインは高く上げるべきだからだ。これを飛ばせば、ループ工学はただの自動カーブフィッティングにすぎない。

Horizon がこのループを回す場所

これが Horizon を中心に据えて構築されたサイクルであり、すべての拍（beat）が1つのフローの中で処理される。あなたは戦略を平易な英語で記述し、すると1つの答えではなく、比較するためのいくつかの variant が提案される。

Horizon はそれぞれをバックテストし、重要な指標（リターン、Sharpe、drawdown）でスコアリングし、何が保ち、何が壊れたかを示す。

あなたは失敗を読み、精緻化し、再び回す。候補が本物に見えたら、何かがライブに行く前に out-of-sample データでゲートされ、そのときに初めて自分の取引所へデプロイされる。クオンツデスクが手作業で回す「生成・テスト・スコアリング・精緻化・デプロイ」のループが、正直なステップを保ったまま、1か所で行われる。タイプして、テストして、生き残ったものを残す。

トレーダーがループ工学を間違える典型

in-sample データでループする。同じ履歴上での速い iteration は、ただ速く過学習するだけだ。ループはゲートで新鮮なデータを必要とする。

スコア関数なしで回す。ICIR のような明確な目的がなければ、ループは何も最適化せず、漂流する。

高い IC を追い、安定性を無視する。素晴らしい IC の1か月は衣装を着ているだけだ。一貫性こそが edge だ。

モデルを method と勘違いする。より良いモデルは生成を速くする。alpha を実際に生み出すのは、ループ、スコアリング、そして out-of-sample ゲートだ。

チェックリスト

始める前に目的を定義する。held-out なウィンドウ上での IC と ICIR。各パスでひと握りの variant を生成する。すべての候補をスコアリングし、失敗を読み、フィードバックする。half-life をチェックし、持続的なシグナルを取引する。生き残ったすべてを out-of-sample データでゲートし、試行回数が増えるにつれて合格ラインを上げる。保つものだけを残す。

モデルは千の factor を書ける。

しかし、どれが本物だったかを教えてくれるのはループだけだ。
