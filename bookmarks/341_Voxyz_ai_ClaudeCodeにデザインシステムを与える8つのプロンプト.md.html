Claude Code / Codex に "デザインシステム" を与える8つのプロンプト

エンゲージメント: Likes 2,957 / RT 189 / Replies 60 / Bookmarks 8,042 / Views 509,759

概要

「Claude Code / Codex に "色が変""フォントがダサい""余白が変" と言うのをやめろ。そもそもデザインシステムを与えていないから defaults を出力し、毎ビルドに難癖をつける羽目になる」という指摘から始まる、コピペで使える8つのプロンプト集（self-thread 連投）。AI に UI を作らせる時、毎回の指示ではなく "システム" を先に与えることでスタイルのブレを止める、という発想。

まとめ

  • 核心: 出力がイマイチなのはモデルのせいではなく、デザインシステム（色・タイプスケール・余白・角丸・影・コンポーネント規則）を渡していないから。
  • 8 つのプロンプト:

1. *Design System* — 散らばった UI・スタイルトークン・反復インタラクションを再利用可能な単一のコンポーネントライブラリに抽象化する。

2. *Accessibility + マルチデバイス* — 通常/弱視/キーボードのみ/異なる端末のユーザー全員がコア操作を完遂できるか、desktop/tablet/phone で実機検証。

3. *DESIGN.md を先に与える* — Google Stitch 由来の概念。色・タイプスケール・余白・角丸・影・コンポーネント規則を plain text で明記し、UI ビルド前に毎回読ませてスタイルのドリフトを止める。「AGENTS.md は作り方、DESIGN.md は見た目」。

4. *UX 監査* — シニア UX デザイナーとして実ユーザー経路を端から端まで歩き、情報階層の弱さ・摩擦・フィードバック欠如・エラー誘発・空/エラー状態を洗い出す。

5. *1 ページを "本物のセンス" で作り直す* — Linear / Stripe 級に。抑えたパレット・明確なタイプスケール・十分な余白・一貫した角丸と影を先に固めてから構築。

6. *全インタラクションと状態を正す* — loading skeleton・空状態・エラー状態・hover/focus/disabled・遷移とフィードバック。

7. *コンバートするランディングページ* — 一行の価値提案と単一の CTA を先に決め、hero/social proof/feature/FAQ/CTA を配置。

8. *フォームを使いやすく* — リアルタイム検証・インラインエラー・妥当な初期値・キーボード/autofill 対応・送信と成否状態・長いフォームはステップ分割。

日本語訳全文（スレッド）

Part 1（親ポスト）

Claude Code / Codex に「色が変」と言うのをやめろ。「フォントがダサい」と言うのをやめろ。「余白が変」と言うのをやめろ。あなたはデザインシステムを与えていない。だから defaults を出力し、毎ビルドに難癖をつける羽目になる。そのままコピペで使える8つのプロンプトとゴールを置いておく。

Part 2

  1. デザインシステム（散らばった UI をコンポーネントライブラリにまとめる） — タスク: このプロジェクトの散らばった UI コンポーネント・スタイルトークン・反復するインタラクションを、再利用可能でメンテしやすい単一の統一デザインシステム（コンポーネントライブラリ）に抽象化せよ。

Part 3

  1. アクセシビリティ＋マルチデバイス — タスク: 通常ユーザー・弱視ユーザー・キーボードのみのユーザー・異なる端末のユーザーの全員が、コア操作を確実に完遂できるようにせよ。現在のコミットからローカルでアプリを起動し、desktop / tablet / phone でコア経路を歩いて確認すること。

Part 4

  1. まず DESIGN.md を与える — DESIGN.md は Google Stitch 由来の概念で、色・タイプスケール・余白・角丸・影・コンポーネント規則を明記した plain text のデザインシステム。エージェントが UI ビルドの前に毎回これを読むことで、スタイルのドリフトが止まる。AGENTS.md が「どう作るか」なら、DESIGN.md は「どう見えるべきか」だ。

Part 5

  1. UX 監査（まず現状を見せる） — このアプリのコアフローを監査するシニア UX デザイナーとして振る舞え。実際のユーザー経路を端から端まで歩け。見つけるべきもの: 弱い情報階層・摩擦・フィードバックの欠如・エラーを誘発するステップ・空状態とエラー状態。

Part 6

  1. 1ページを「本物のセンス」で作り直す — プロダクトデザイナーとして、このページを Linear / Stripe のような質感に作り直せ。先にスタイルを固めること: 抑制されたパレット・明確なタイプスケール・十分な余白・一貫した角丸と影。そのうえで構築する。

Part 7

  1. すべてのインタラクションと状態を正す — シニアフロントエンドエンジニアとして、すべてのインタラクションと状態を正しく実装せよ。カバーすべき項目: loading skeleton・空状態・エラー状態・hover / focus / disabled、加えて主要アクションの遷移とフィードバック。

Part 8

  1. コンバージョンするランディングページを作る — コンバージョン志向のデザイナーとして、ランディングページを作れ。まず一行の価値提案と、訪問者に取ってほしい単一のアクションを決める。そのうえで hero・social proof・feature セクション・FAQ・CTA を配置する。

Part 9

  1. フォームを使いやすくする — シニアフロントエンドエンジニアとして、このフォームを使いやすくせよ。カバーすべき項目: リアルタイム検証・明確なインラインエラー・妥当な初期値・キーボード/autofill 対応・送信中と成功/失敗の状態・長いフォームはステップに分割。
