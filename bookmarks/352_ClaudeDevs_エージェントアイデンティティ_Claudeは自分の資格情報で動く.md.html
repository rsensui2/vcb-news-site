Claude の「エージェント・アイデンティティ」— 共有チャンネルでは Claude 自身の資格情報で動く

№089 / 506 SRCx.com/ClaudeDevs ↗ GHGitHub ↗
089BOOKMARK / 506

有益度: ⭐⭐⭐⭐

エンゲージメント: Likes 2,948 / RT 165 / Replies 147 / Bookmarks 1,163 / Views 313,493

概要

Anthropic 公式（ClaudeDevs）が、複数人がいる共有チャンネルで Claude が動くときに「誰の権限（資格情報）を使うのか」という問いに答えたスレッド。結論は「Claude 自身の権限」。チームに Claude をタグ付けすると、Claude は他のメンバーと同じように自分専用のアカウント／資格情報を割り当てられる。この仕組みを agent identity（エージェント・アイデンティティ） と呼ぶ。

まとめ

  • DM とチャンネルで挙動が違う: 1 対 1 の DM では Claude は「あなたとして」動く（あなたのコネクタ・あなたの名前で。個人メールやカレンダーはここが定位置）。3 人以上いる共有チャンネルでは「借りるべき正しい権限セット」が存在しないため、Claude は「Claude 自身として」動く。
  • agent identity の中身: チャンネルでは Claude が自分専用の Linear アカウント・GitHub アカウント・データウェアハウスのサービスアカウントを持つ。人間のチームメイトと同じ扱いでプロビジョニングされる。
  • 管理者による制御: 管理者が一度プロビジョニングし、チャンネルごとに到達範囲をスコープできる。共有スペースでは広い読み取り権限、機微なツールは限られた人だけがいる場所でのみ、といった粒度で制御。
  • 設計思想: 「共有作業で役立つ程度のアクセスは Claude に与えつつ、それがどこで止まるかは管理者が正確にコントロールする」。

原文

When Claude is working in a channel with four people, whose credentials does it use?
The answer: its own. When tagging Claude, Claude gets provisioned like any other teammate, with its own credentials.
We call this access model "agent identity". Here's how it works: 🧵

スレッド全体

Part 1 (親ポスト)

4 人いるチャンネルで Claude が作業するとき、誰の資格情報を使うのか? 答えは「Claude 自身のもの」。Claude をタグ付けすると、Claude は他のチームメイトと同じように自分専用の資格情報でプロビジョニングされる。このアクセスモデルを「agent identity」と呼ぶ。

Part 2

1 人の個人アシスタントなら「ユーザーとして振る舞う」で問題ないが、Claude Tag はマルチプレイヤーになりうる。3 人が 1 つのスレッドにいると、借りるべき「正しい」権限が存在しない。だからチャンネルでは Claude は自分自身として、DM ではあなた自身として振る舞う。

Part 3

DM は単純なケース: Claude はあなた自身のコネクタ上で、あなたの名前で動く。個人メールやカレンダーはそこに属する。チャンネルでこそ agent identity が効いてくる。Claude は自分の Linear アカウント、自分の GitHub アカウント、ウェアハウスの自分のサービスアカウントを持つ。

Part 4

管理者が一度プロビジョニングし、チャンネルごとに到達範囲をスコープする: 共有スペースでは広い読み取りアクセス、機微なツールはクリアされた数人がいる場所だけ。設定手順は Noah のビデオで解説。

Part 5

Claude には共有作業で役立つだけのアクセスを与え、管理者はそれがどこで止まるかを正確にコントロールする。詳細はブログで。
