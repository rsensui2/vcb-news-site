Claude Code の性能を引き出す CLAUDE.md 設計術 — 「メモ帳」ではなく「判断の地図」にする 5 要素

有益度: ⭐⭐⭐⭐

エンゲージメント: Likes 146 / RT 5 / Bookmarks 521 / Views 163,915

概要

Claude Code が作業前に必ず読み込む CLAUDE.md を、思いついた指示を継ぎ足す「メモ帳」ではなく、AI が毎回参照する「判断の地図」として設計せよ、という記事。Anthropic 公式どおり CLAUDE.md はフォルダにあれば作業開始前に必ず読まれるため、ここの中身で AI の初動が 100% 変わる。長すぎる CLAUDE.md（200 行超）はかえって重要度が埋もれる、と警告する。

まとめ

  • CLAUDE.md は毎会話に効く「一度書けば全会話に適用される」高レバレッジな設定。プロンプトを磨いても、ここが整っていないと恩恵はほぼゼロ。
  • 推奨は 200 行以内。長すぎると「どれが重要か分からない長文」になり、AI が毎回全体を読み直して「今回はどれに当てはまる?」と推測する → ブレる。
  • 強い CLAUDE.md に共通して入る 5 要素:

1. 最優先ルール — 出力前に必ず従わせる先頭の宣言（「考える前にまず下のルールに従え」と釘を刺す）

2. キーワード→置き場のルーティング表 — どの仕事をどこに置く/見るかを普段の言葉で対応づけ。軸は「事業」でなく「機能（やること）」で切る

3. 置き場の決定木 — 表に無いものを上から YES/NO で辿らせ、迷う余地を消す（記事いわく「ここが一番効く」）

4. タスクの扱い方 — やることをどこにどう残すか固定

5. 機密情報の扱い — 外に出してはいけないものの線引き（API キー・パスワードは .env へ 等）

  • 効果: AI が「推測」をやめ「参照」で動く → 同じ依頼に毎回同じ動きをして再現性が出る。決定木の最後に「決まらなければ突っ走らず質問せよ」と書くと、自信満々の的外れ成果物が構造的に減る。
  • 教訓: 賢い AI ほど、自由にさせるより「型」を渡したほうが性能が出る。
