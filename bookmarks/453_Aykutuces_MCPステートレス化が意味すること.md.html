「MCPはもうAIのUSB-Cだけじゃない」— ステートレス化がインフラ選択に何をもたらすかの解説（トルコ語）

投稿本文（原文・トルコ語）

MCP protokolü bugün en büyük güncellemesini aldı. Kimse ne olduğunu tam anlamadı ama bu tarih değiştiren tarafta.

Eski MCP: her session'ın state'ini serverda tutmak lazımdı. Yani serverless çalışmıyor, edge'e atamıyor, load balancer arkasına sticky session'la bağlıyordun. Enterprise için can sıkıcı, indie geliştirici için pahalı.

Yeni MCP: stateless. Artık server'ı Cloudflare Workers'a, Vercel Edge'e, tek satır YAML ile Kubernetes cluster'a atıyorsun. Load balancer round-robin, sonsuz yatay scale.

Üstüne üç yeni katman geldi:

MCP Apps: agent'ın kendi UI'ını sandbox iframe içinde render ediyor
Tasks: uzun süren async operasyonlar
Enterprise Managed Auth: identity provider'dan merkezi erişim kontrolü

MCP artık sadece "AI'ın USB-C'si" değil. Server'ı stateless, UI'ı render eder, uzun task'ları arka planda çalıştırır, SSO ile enterprise kilidini açar.

（引用ポスト: @ClaudeDevs 「MCP 2026-07-28 is live and it's the largest update to the protocol since launch. MCP is now stateless, making it easier to deploy and scale remote servers.」）

概要

MCP 2026-07-28 のステートレス化を、インフラ担当者の実務目線で言い直した解説ポスト。公式発表が「デプロイとスケールが容易になる」と書いている部分を、旧仕様で実際に何が面倒だったか（sticky session を張らねばならず、serverless に載らず、エッジに置けない）と、新仕様で何が選べるようになるか（Cloudflare Workers / Vercel Edge / YAML 一行で Kubernetes、ロードバランサは round-robin で無限水平スケール）に落として説明している。「誰もこれが何なのか正確には理解していないが、歴史を変える側の変更だ」という書き出しが要点をよく表している。

まとめ

  • 旧 MCP の制約: セッションごとの state をサーバ側に保持する必要があった。結果として serverless では動かず、エッジに置けず、ロードバランサの背後では sticky session で紐付ける必要があった。エンタープライズには煩わしく、個人開発者にはコストが高い
  • 新 MCP: ステートレス。サーバを Cloudflare Workers や Vercel Edge に置ける。YAML 一行で Kubernetes クラスタに載せられる。ロードバランサは round-robin でよく、水平スケールが事実上無制限
  • 上に乗った3つの新レイヤー:

- MCP Apps — エージェント自身の UI をサンドボックス iframe 内でレンダリングする

- Tasks — 長時間実行の非同期オペレーション

- Enterprise Managed Auth — ID プロバイダからのアクセス制御の中央集約

  • 結論の一文: MCP はもはや「AI の USB-C」だけではない。サーバはステートレスで、UI をレンダリングし、長時間タスクをバックグラウンドで走らせ、SSO でエンタープライズの鍵を開ける
  • 公式の @ClaudeDevs 投稿を引用しての解説であり、一次情報は公式リリース側にある

日本語訳全文

MCP プロトコルは今日、最大の更新を受けた。誰もそれが何なのかを正確には理解していないが、これは歴史を変える側の変更だ。

旧 MCP: セッションごとの state をサーバ側に持つ必要があった。つまり serverless では動かず、エッジに置けず、ロードバランサの背後には sticky session で紐付けていた。エンタープライズには煩わしく、個人開発者にはコストが高い。

新 MCP: ステートレス。もうサーバは Cloudflare Workers にも Vercel Edge にも置けるし、YAML 一行で Kubernetes クラスタに投げられる。ロードバランサは round-robin、水平スケールは無限。

その上に3つの新しいレイヤーが乗った:

MCP Apps: エージェント自身の UI をサンドボックス iframe 内でレンダリングする
Tasks: 長時間実行の非同期オペレーション
Enterprise Managed Auth: ID プロバイダからのアクセス制御の中央集約

MCP はもう単なる「AI の USB-C」ではない。サーバはステートレスで、UI をレンダリングし、長時間タスクをバックグラウンドで走らせ、SSO でエンタープライズの鍵を開ける。

（引用ポスト: @ClaudeDevs 「MCP 2026-07-28 が公開。ローンチ以来プロトコル最大の更新です。MCP はステートレスになり、リモートサーバのデプロイとスケールが容易になります。」）
