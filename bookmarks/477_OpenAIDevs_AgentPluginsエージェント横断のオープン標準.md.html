Part 1 (親ポスト)

プラグインを一度作れば、対応するあらゆるエージェントクライアントで使える。

Agent Plugins を発表します。AWS Developers、Cursor、GitHub、VS Code、Vercel と共同で策定したオープン標準で、Agent Skills をパッケージ化し、MCP サーバー設定を共通フォーマットでサポートします。

ローンチ時点で対応するエージェントクライアント:

公式ドキュメントからの補足（developers.openai.com/codex/plugins）

プラグインは以下の要素を1つ以上まとめた配布単位:

  • Skills: 特定の作業のための再利用可能な指示。必要になったときにエージェントがロードする
  • Connectors: GitHub / Slack / Google Drive などへの接続。ツールを公開し、カスタム UI も持てる
  • MCP servers: 外部システムに対してツール定義・認証・構造化データ返却・アクション実行を担う。Connectors の実体でもある
  • Browser extensions: そのワークフローに必要なブラウザ機能
  • Hooks: 設定したライフサイクル地点で走るコマンド（有効化前にレビューして信頼すること、と公式が警告）
  • Scheduled task templates: 定期タスクの再利用可能な雛形

配布はマーケットプレイスソース経由（プロジェクト／チーム単位の repo marketplace など）。ChatGPT と Codex は同一の公開プラグインカタログを共有する。Codex CLI では /plugins でブラウザを開いてインストールし、新規セッションから利用可能になる。

Summary

OpenAI が、AWS・Cursor・GitHub・VS Code・Vercel と共同で策定した「Agent Plugins」というオープン標準を発表した。Agent Skills（エージェント向けの再利用可能な手順書）と MCP サーバー設定を1つのパッケージにまとめ、共通フォーマットで配布できるようにするもの。ローンチ時点で Codex / ChatGPT / Cursor / GitHub Copilot / Kiro / VS Code の6クライアントが対応する。プラグインには Skills・Connectors・MCP サーバーに加え、ブラウザ拡張・Hooks・定期タスク雛形も同梱でき、ChatGPT と Codex は同一の公開カタログを共有する。

Key points

  • 「一度作れば全クライアントで動く」が設計目標: エージェントごとにスキルを移植する手間をなくす
  • 策定は OpenAI 単独ではない: AWS Developers / Cursor / GitHub / VS Code / Vercel との共同。競合を含む横断標準として立ち上げた
  • ローンチ対応6クライアント: Codex、ChatGPT、Cursor、GitHub Copilot、Kiro、VS Code
  • Skills と MCP を1パッケージに束ねる: 「手順書」と「ツール接続」がバラバラだった配布単位を統合した
  • 同梱できるのは6種: Skills / Connectors / MCP servers / ブラウザ拡張 / Hooks / 定期タスク雛形
  • Hooks はセキュリティ注意点として明記: ライフサイクル地点で任意コマンドが走るため、公式が「有効化前にレビューして信頼を確認しろ」と警告している
  • 配布はマーケットプレイス経由: repo marketplace でチーム内配布も可能。ChatGPT / Codex は共通の公開カタログ
  • 反響は桁違い: 209万インプレッション・ブックマーク4207件

Takeaway

Anthropic が Agent Skills をオープン仕様として出した流れを、OpenAI が「配布パッケージ」のレイヤーまで引き上げて業界標準化しにきた形。MCP が「エージェント⇄ツール」の接続を標準化したのに対し、Agent Plugins は「Skill + MCP設定 + hooks + 定期タスク」をまとめて配る単位を標準化する。つまり *エージェント運用ノウハウそのものが流通可能な資産になる* ということで、社内で育てたスキルを Cursor でも Copilot でも VS Code でも同じパッケージで配れる。

注意点は Hooks。ライフサイクルで任意コマンドが走る仕様なので、外部マーケットプレイスからプラグインを入れる運用は、npm の postinstall と同じクラスのサプライチェーンリスクを持つ。公式が名指しで警告しているのは、そこが最大の攻撃面だと分かっているから。組織導入するなら「hooks を含むプラグインは要レビュー」を最初にルール化しておくべき。
