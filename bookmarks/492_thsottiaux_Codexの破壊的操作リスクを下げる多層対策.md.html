Codex が誤ってファイルを消す問題への多層対策（OpenAI 公式・Codex 責任者）

日本語訳全文

こんにちは！

Codex が作業中に破壊的な操作をしてしまうリスクを、この数週間でさらに下げました。その変更をまとめます。

数週間前、Codex の GPT-5.6 がユーザーの依頼していない破壊的な操作をした、という報告が少数寄せられ、調査を始めました。いちばん深刻だったのは、一時作業を片付けるはずのコマンドが、代わりにユーザーのファイルを消してしまう可能性があったというパターンです。これは当然あってはならないことです。

わかったのは次の2点です。

  • Codex は作業中に一時フォルダを作り、あとで片付けます。まれに GPT-5.6 がこの片付けを誤りました。ひとつのパターンは、$HOME のようなシステム環境変数を一時作業用に流用してしまうこと。片付けコマンドの組み立てが崩れると、一時フォルダではなく実際のホームディレクトリを指してしまいます。
  • 一時パスに何が既に置かれているか確認しないまま、削除・上書きしようとするケースもありました。

対策は複数の層に入れました。

  • Codex に対して、削除対象を実行前に確認する／一時ディレクトリは毎回新規に作る／システム環境変数を流用しない／復旧可能な操作を優先する／範囲が曖昧なら止まる、を明示的に指示。
  • 危険度の高い削除コマンドを検出してレビューに回す実行時チェックを強化。コマンドが弾かれた場合は、モデルにより安全な方法を取るよう誘導。
  • Full access（フルアクセス）を誤って有効化しにくくし、警告を明確化。特に危険な権限の組み合わせをさらに制限。
  • Auto-review が破壊的操作をより正確に検出するよう更新。
  • 観測された失敗を再生する専用の評価を構築。これらのリスクに焦点を当てた強化学習タスクと採点器も追加中で、学習データからも破壊的操作を除外している。

この再生評価では、通常のコーディング作業をこなす能力を保ったまま、問題挙動を大幅に減らせました。

ユーザー側でやってほしいことが2つあります。

  • Codex アプリを最新に保つこと。安全性・性能ほか常に改善しています。
  • サンドボックスモード（"Ask for approval" か "Approve for me"）のどちらかを使うこと。Full access は、信頼できて復旧もできる環境だけにしてください。

それでは、よい Codex ライフを！

まとめ

OpenAI の Codex 責任者 Thibault Sottiaux が、GPT-5.6 搭載 Codex による意図しないファイル削除の調査結果と対策を公開した。原因は「一時フォルダの片付け」処理の失敗で、$HOME などのシステム環境変数を一時作業に流用した結果、片付けコマンドが実際のホームディレクトリを指してしまうパターンが最も深刻だった。対策はモデル指示・実行時チェック・権限UI・Auto-review・評価/学習データの5層に入っており、再生評価では通常のコーディング能力を落とさずに問題挙動が大幅に減ったとしている。ユーザー側の推奨は「アプリを最新に保つ」「Full access ではなく承認付きサンドボックスモードを使う」の2点。
