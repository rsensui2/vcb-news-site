Codex CLI 0.130.0 — `codex remote-control` でスマホ/外出先から自宅マシンを操作可能に

OpenAI が Codex CLI 0.130.0 をリリース。トップレベル新コマンド `codex remote-control` で headless かつ remotely controllable な app-server を起動できる。自宅 Mac で動かす Codex に、外出先のブラウザ（事実上スマホ）から接続して作業継続・追加指示が可能になった。

キーポイント

  • `codex remote-control` で headless app-server が起動、別端末から接続可能
  • プラグイン共有が link metadata + discoverability controls 付きで強化
  • Bedrock 認証が AWS console-login profile 経由でサポート
  • @Codestudiopjbk が日本語解説で 368L、@hAru_mAki_ch 194L、@neromeron1014 が tailscale+自宅 MacbookPro で `codex_mobile` を自作
  • 公式 @Codex_Changelog 側でも 1,048L で告知
「コーディングエージェントを家のマシンで走らせ、移動中のスマホから様子見・追加指示する」運用が純正コマンド化された。VBC や tekion エンジニアにとって長時間タスクを止めずに進める現実解になる。Codex は token 効率・速度に加え「体験」面でも先行し始めた。

Claude Code「Routines」— `/schedule` で定期実行 AI ジョブを 1 行設定

Claude Code に「Routines」機能が追加。`/schedule` コマンドで cron 風に繰り返し AI ジョブを設定すれば、それ以降 Claude がローカル/リモートで自走する。例: `/schedule PR review daily at 9am`、毎週月曜の CHANGELOG レビュー、毎朝 Slack 情報要約を DM に送る、など。

キーポイント

  • `/schedule <prompt>` 1 行で定期実行をセット
  • ローカル/リモート両対応
  • PR レビュー、リリースノート生成、日次サマリ等のユースケース
  • Claude Web 側の Routine (5-08 頃 @zento_ai が「Slack 情報を DM に送る」を実装) と対応する CLI 版
  • 評価は割れる: 「便利」(@aya_happy_life) vs 「GitHub Actions の方が今は強い、もっとリソース投下を」(@Rames_Jusso)
これまで Ryoko が cron + child session で実装していた「定期実行 AI ジョブ」が Claude Code 純正機能化。VBC 受講生にとっては YAML や別ツール無しで「毎朝の PR レビュー」「日次レポート」を仕込める。Ryoko の cron 設計と直接比較できるリファレンスになる。

16人エンジニアチームが Anthropic 解約 → Codex+Cursor へ — トークン効率議論が再燃

Morgan Linton（16 人エンジニアリングチームのリーダー）が Anthropic プランを正式に解約し、Codex + Cursor 中心の運用に切り替えたと公表。理由は純粋にコスト: Anthropic は月 $2,000/人 × 16 人 = $32,000/月 になる構造で支払い切れない。Codex は GPT-5.5 で精度・トークン効率が大幅に向上、Cursor Composer 2 もチーム運用で limit に当たらない。

キーポイント

  • 16 人 × $2,000/月 = $32,000/月 を支払い切れないという経済性が主因
  • 「Codex は so good, and so token efficient」「Cursor は limit に当たらない」
  • レビューは引き続き人手で多くこなす（最終判断は人前提を維持）
  • Droid も並行検証中
  • @techedgedaily: 「Anthropic は能力ではなく経済性で負けた」
  • @PulkitMehrotra: Codex installs 86.1M / Claude Code 7.2M（5 月初・週次）
Anthropic は 5-08 に Claude Code 利用上限を倍増したばかりだが「中小チームには高すぎる」声が出始めた。VBC（個人 or 小規模チーム）にとって「Claude / Codex / Cursor をコスト最適で組み合わせる」設計が現実の宿題に。tekion で 16 人前後の開発組織がある場合も同じ計算が当てはまる。

OneBiz: Claude Code でプレゼン資料を 5 ステップで作る — PowerPoint/Slides を捨て HTML+GitHub Pages へ

OneBiz が X long-form で「Claude Code を使ったプレゼン資料の作り方 5 ステップ」を公開。PowerPoint/Google Slides は AI 時代の制約になっていると主張し、Claude プロジェクト + システムプロンプトテンプレ → チャット編集（最大 2 回） → Claude Code 仕上げ → GitHub Pages デプロイ という HTML プレゼン制作ワークフローを解説。

キーポイント

  • 5 ステップ: (1) スクリプト準備 (2) Claude プロジェクトに再利用システムプロンプト+Knowledge (3) チャット編集は 2 回まで (4) Claude Code (`npm i -g @anthropic-ai/claude-code`) で細部仕上げ (5) GitHub Pages で URL 共有
  • システムプロンプト推奨要素: 単一HTML/CSS&JSインライン、スライド最大3行、ダークBG(#0a0a0a→#1a1a2e)+アクセントカラー、CSS animation、矢印キー操作
  • 「構造変更はチャット、細部は Claude Code」の使い分け
  • チャット 3 回目以降はコンテキスト汚染で品質劣化するから止める
  • GitHub Pages は `index.html` をルート配置 + Settings → Pages → main を選ぶだけ
Vibe Coder Bootcamp 受講生・社内エンジニアにとって「Claude でプレゼンを作る」を再現可能なワークフロー化した実践メモ。Thariq の「HTML is the new markdown」(5-08) の応用ユースケースで、Claude プロジェクト + Claude Code + GitHub Pages の組み合わせを学ぶ素材として最適。

Chormex に GPT-Realtime-2 でリアルタイム翻訳 + Codex で同時要約 — 「ブラウザ = リアルタイム AI OS」

CHOI が自身の Chrome 拡張「Chormex」に GPT-Realtime-2 を組み込み、Chrome 内で再生される全音声（YouTube / ライブ配信 / 会議 / プレゼン）をリアルタイム翻訳しつつ、同時に Codex で要約・ノート化・整理を行える機能を追加。「ブラウザはリアルタイム AI OS に進化している」「インターネット上の言語の壁が消えつつある」と主張。

キーポイント

  • GPT-Realtime-2 を使った低レイテンシ翻訳 + LLM 解析の同時実行
  • 対象は Chrome 内の音声: YouTube, ライブ配信, 会議, プレゼン
  • 操作例: 'Summarize this.' / 'What are the key points?' / 'Turn this into notes.' / 'Explain what they mean.' / 'Organize the discussion.'
  • GitHub リポジトリも公開（スレッド Part 2 でリンク）
  • GPT-Realtime-2 商用ユースケースの 2 件目（OpenAI 公式に続く Chrome 拡張組み込み事例）
GPT-Realtime-2 を「単なる音声合成」ではなく「ブラウザ拡張で常時走るリアルタイム AI 基盤」として使う設計の参考実装。VBC で「AI を組み込んだブラウザ拡張」の構成例として直接使える。tekion 側でも会議録/翻訳ニーズに転用可能。
