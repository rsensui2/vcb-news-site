03TOPIC 03 · ANTHROPIC / CLAUDE

Anthropic、Claude Code に /goal を正式紹介 — 完了条件まで止まらない「Ralph loop」を純正機能化

Anthropic 公式が Claude Code の新コマンド `/goal` を 6 ポストのスレッドで実演。完了条件を指定（例: `/goal all tests in test/auth pass and the lint step is clean`）すると、Claude は条件達成までトランスクリプトに対して停止判定を自分で拒否する（Ralph loop）。`/schedule`（cron 風定期実行）、`/loop`（反復実行）、auto モード（shift+tab で人間待ち排除）、stop hook（test 実行や CI ヒットで完了条件をプログラム制御）と組み合わせて長尺タスクが完走する設計。

キーポイント

  • /goal <完了条件> で Claude が条件達成までトランスクリプトを自分でチェック
  • 達成時は「Goal achieved」サマリーが返る
  • /schedule で cron 風スケジュール、/loop で反復、auto モードで shift+tab
  • stop hook で test スイートや CI エンドポイントを完了条件に組み込み可能
  • Claude Code Log によれば Claude Code 2.1.139 リリースに含まれる（[ClaudeCodeLog 解説](https://x.com/ClaudeCodeLog/status/2053913625983692979) ）
Ryoko の cron + child session 設計と Claude Code 純正機能の使い分け論点がさらに具体化。VBC 受講生にとっては「夜間ジョブを自前で書かずに /goal + /schedule で完走させる」が現実解になる。Topic 1 の上限増と組み合わせて「上限が増えた → 長尺ジョブを /goal で回す」連動ストーリーが描ける。

BOOTOSHI、npm サプライチェーン攻撃の即時防御プロンプトを公開 — Codex/Claude Code に貼るだけで 4 ステップ実行

TanStack 起点で 170+ パッケージ・週 DL 1 億+ に拡大した npm「Mini Shai-Hulud」攻撃を受け、BOOTOSHI が Codex / Claude Code にそのまま貼って実行できる防御プロンプトを公開。`~/.npmrc` / `~/.bunfig.toml` に最小公開待機日数 7 日を設定し、`package.json` の全依存をピン留め、lockfile を git commit する 4 ステップ構成。「直近 7 日に出たバージョンを全 package manager が拒否する」クールダウン戦略で、攻撃チェーンが通常数時間で消えるバッファを上回る。

キーポイント

  • `~/.npmrc` に `min-release-age=7` / `minimum-release-age=10080` / `save-exact=true` を追加（npm 全体クールダウン）
  • `~/.bunfig.toml` に `[install] minimumReleaseAge = 604800` を追加（bun も同様）
  • `package.json` の全依存から `^` `~` を剥がして完全一致バージョンに固定
  • lockfile（bun.lock / package-lock.json / pnpm-lock.yaml）を git commit
  • Mini Shai-Hulud は CI パイプライン乗っ取りで SLSA 3 級署名済みのまま配布される（[詳細解説 by AYi](https://x.com/AYi_AInotes/status/2054225365548036576) ）
  • AI Agent 経由の自動 install が最大被害層
従来の「公式署名なら信頼」ロジックが崩れた中、AI 中心開発者ほど自動 install 頻度が高く被害確率が高い。VBC / Tekion 開発者に即時配布できる「コピペで効く」防御策が公開された意義は大きい。Cursor cloud agents（Topic 4）のような「使い捨て環境」も中長期の構造的回答だが、今すぐ効くのはこのプロンプト。
