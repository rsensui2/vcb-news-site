AIコーディングエージェントの「セキュリティ」が新たな主戦場に — OpenAIが公式ガイダンス、脆弱性・防御ツールも続々

OpenAI が『プロンプトインジェクションに耐えるエージェント設計』の公式ガイダンスを公開し、完全な検知は期待せず影響範囲を限定する現実的な構えを打ち出した。同時期に Johns Hopkins が Claude Code / GitHub Copilot を騙して内部情報を漏らさせる脆弱性を報告し、依存ライブラリにプロンプトインジェクションを仕込む手口や、Keeper Security のシークレット安全取得フレームワーク『Agent Kit』など、攻撃と防御の両面が一気に表面化した。

キーポイント

  • OpenAI 公式: 防御は入力フィルタだけに頼れず、最小権限・タスク単位のアクセス制限・重要操作の二段階承認・検知重視を推奨
  • OpenAI は『プロンプトインジェクションは（ブラウザ/エージェントで）完全には解決しないかもしれない』と明言
  • Johns Hopkins が Claude Code / Copilot を操作して内部情報を漏洩させる脆弱性を公表
  • 依存ライブラリにプロンプトインジェクションを埋め込み、AI 生成コードの出力を無言で破壊する PoC が話題に
  • Keeper Security が『Agent Kit』を提供開始、コーディングエージェントが認証情報を安全に取得する枠組み
コーディングエージェントが本番コードを書く前提になった今、『速く書ける』より『安全に動かせるか』が次の論点。OpenAI の公式スタンスが『検知重視・最小権限』に振れたことで、VBC 受講生がエージェントを業務に組み込む際の設計指針が明確になった。

Cognition（Devin 開発元）が約10億ドルを調達、評価額260億ドルに — 自社コードの89%を Devin が記述

自律ソフトウェアエンジニアリングエージェント『Devin』を開発する Cognition が、Lux Capital・General Catalyst・8VC 主導で10億ドル超を調達し、調達後評価額は260億ドルと前回（昨年9月）から倍以上になった。創業者 Scott Wu は『Devin はプログラマを置き換えるためではなく支援するためのもの』と強調する一方、Cognition は自社エンジニアがコミットするコードの89%は Devin によるものだと明かした。

キーポイント

  • 調達額10億ドル超、評価額260億ドル（前回比2倍超）
  • 主導は Lux Capital / General Catalyst / 8VC、Founders Fund・Ribbit なども参加
  • 売上は1年で13倍の4.92億ドル、顧客に Goldman Sachs や Mercedes-Benz
  • 自社コミットコードの89%を Devin が記述
  • Scott Wu『エージェントは人間を置き換えるものではなく支援するもの』
コーディングエージェント市場への資金流入が止まらないことを示す象徴的なラウンド。『89%のコードを AI が書く』は VBC が掲げる Vibe Coding の到達点を地で行く数字であり、エージェント前提の開発組織が現実になっている証拠。

StepFun が「Step 3.7 Flash」をオープンウェイトで公開 — 198B MoE・Apache 2.0・最大400トークン/秒

中国の StepFun が高効率モデル『Step 3.7 Flash』をオープンウェイトで公開した。196B の言語バックボーンと1.8B のビジョンエンコーダからなる198BパラメータのスパースMoE（推論時アクティブ約11B）で、256Kコンテキスト・マルチモーダル・エージェント型ツール利用に対応する。ライセンスは Apache 2.0、生成速度は最大400トークン/秒で、SWE-bench Pro などのベンチでオープンモデル最高水準を主張している。

キーポイント

  • 198BパラメータMoE、アクティブ約11B/トークン、最大400トークン/秒
  • 256Kコンテキスト、画像・動画理解に対応するビジョン言語モデル
  • ライセンスは Apache 2.0（商用利用可のオープンウェイト）
  • エージェント型コーディング・ツール利用・長文推論・検索を主用途に設計
  • 提供先: StepFun Open Platform / OpenRouter / NVIDIA NIM、vLLM・SGLang・llama.cpp で動作
クローズドな Opus 4.8 / GPT-5.5 / Gemini が話題を独占する裏で、オープンウェイト陣営も速度と効率で実用ラインに到達しつつある。Apache 2.0 で自己ホスト可能な agentic coding モデルは、機密データを外に出せない企業やコストを抑えたい VBC 受講生に有力な選択肢。

Claude Code「Dynamic Workflows」が実戦で高評価 — Opus 4.8 の目玉機能

Opus 4.8 と同時に発表された Claude Code の『Dynamic Workflows』（計画→数百の並列サブエージェント→自己検証→報告を動的に組む研究プレビュー機能）が、公開直後から開発者の間で『久々に最も価値あるアップデート』と高評価を集めている。あわせて『タスク途中で Claude の指示を差し替えてもプロンプトキャッシュを壊さない』改善も実装の妙として注目された。

キーポイント

  • Dynamic Workflows は計画→並列サブエージェント→自己検証→報告を動的に構成する研究プレビュー機能
  • 『ここ最近の Claude Code で最も価値あるアップデート』との実戦評価が複数
  • タスク途中で system 指示を差し込んでも prompt cache が壊れない設計が好評
  • effort control（思考量の制御）と組み合わせた長時間タスクの安定運用が狙い
単体モデルの賢さ競争から『エージェントの実行ハーネスをどう組むか』へ関心が移っている象徴。VBC で教えるマルチエージェント設計（Hub & Spoke、自己検証）をツール側が標準機能化したもので、受講生が手で組んでいた構造を Claude Code が肩代わりし始めている。

Opus 4.8 は経験豊富なエンジニアのように、逐一の確認なしで判断する（Claude 公式）

Anthropic 公式が Opus 4.8 の自律性を訴求した投稿。Claude Code 上で経験豊富なエンジニアのように逐一の確認なしで判断し、長時間に及ぶセッションでも軌道を外さずリポジトリ内のタスクを最後までやり遂げると説明する。機能追加やバグ一掃を丸ごと任せ、人間は次の作業に集中できると打ち出している。

キーポイント

  • Claude Code で Opus 4.8 は『経験豊富なエンジニアのように』逐一の確認なしで判断
  • 長時間セッションでも軌道を外さずリポジトリ内の作業を完遂
  • 機能追加やバグ一掃を丸ごとハンドオフできる自律性を強調
無人実行（unattended agent）の実用化メッセージ。人が張り付かずに大きめのタスクをエージェントへ任せる設計の根拠になり、Kenn 氏の『Opus は頭脳役』という実践論とも符合する。

Opus 4.8 に Fast モード登場 — 同じモデルで約2.5倍速・従来比3倍安（Claude 公式）

Anthropic 公式が Opus 4.8 の Fast モードを発表した投稿。モデル自体は同一で速度が約2.5倍、価格は従来比3倍安になる。Claude Code では /fast で即座に切り替えられ、API 利用はアカウントマネージャー経由かウェイトリスト登録が必要となる。

キーポイント

  • Fast モードは Opus 4.8 で利用可能、同一モデルのまま約2.5倍速・従来比3倍安
  • Claude Code では /fast で即切替
  • API はアカウントマネージャー連絡 or ウェイトリスト登録（claude.com/fast-mode）
『精度を落とさず速度と価格だけ改善』という珍しい改善軸。レイテンシが効くインタラクティブ作業や大量並列エージェントのコスト計算を変える。VBC 受講生にも即案内できる実用情報。

大規模開発は「人間 ←→ Opus ←→ Codex」の多重下請け構造がおすすめ（Kenn Ejima）

Kenn Ejima 氏が大規模開発でのマルチエージェント開発フローを self-thread で整理した投稿。『人間 ←→ Opus ←→ Codex』の多重下請け構造を勧め、Opus を意図理解・レビュー・リファクタ指摘の頭脳、Codex を実装の手と役割分担する。プランは Codex に書かせて Claude にレビューさせ、実装は Codex に戻す。Claude は『読んで考えるだけ、docs 以外は書かせない』のが肝だとする。

キーポイント

  • 大規模開発は『人間 ←→ Opus ←→ Codex (←→ Cursor)』の多重下請け構造が有効
  • Opus は意図・本質をつかむのが得意だがコードを書かせると手戻りが多い／Codex は実装が漏れない反面、細部にとらわれ本質を見落とす
  • プランは Codex に書かせ Claude にレビューさせる（Claude のプランは詳細に踏み込みすぎるのでツッコミ役に徹させる）
  • Codex の『安全だが汚い』コードは最後に Claude がリファクタを指摘し、実作業は Codex 本人に戻す
  • 結論: Claude は読んで考えるだけ、docs 以外は書かせない
『1体のAIに全部やらせる』から『複数AIを役割分担させる』への転換点になる実践知。手戻りを減らす再現性の高いテクニックで、Opus 4.8 のレビュー精度向上や Dynamic Workflows とも整合する。
