Claude Code 2.1.251、権限境界の修正とキャッシュ可視化を同時に実施

AnthropicはClaude Code 2.1.251を公開した。モデル切替の前後に介入できるフック、`/cost`のプロンプトキャッシュ表示、`/usage`の支出上限表示を加え、承認後にシンボリックリンクを差し替えて許可範囲外へ到達できる不備などを修正している。

キーポイント

  • `PreModelSwitch`と`PostModelSwitch`で、モデル切替を停止・確認・注釈できる
  • `/cost`にキャッシュヒット率、ミス、再キャッシュ量、warm/coldの表示を追加した
  • ファイル操作、Grep/Glob、Workflow、プラグインコマンドの境界検査を強化した
  • サブエージェントの最終回答がチームリードへ届かない不具合を修正した
  • 並列サブエージェント実行時のTUI遅延と、強制停止後に残るBashプロセスも修正した
長時間・並列でエージェントを動かすほど、キャッシュ費用と権限境界の観測が運用品質を左右する。今回の更新は便利機能より、承認後のパス差し替えを塞いだ点を先に評価したい。

Codex CLI 0.151.0、MCPの結果をモデルへ渡す前に検査可能に

OpenAIはCodex CLI 0.151.0を公開した。拡張機能がMCPツールの結果を検査・置換できる仕組みを加え、ネストしたサブエージェントのトークン消費を親ゴールの予算へ計上するようにした。

キーポイント

  • MCPツールの結果をモデルへ渡す前に、拡張機能が検査・置換できる
  • 任意MCPサーバーの起動待ち時間を設定できる
  • リポジトリ単位の設定をプラグインカタログへ統合する
  • ネストしたサブエージェントの消費量を親ゴールの予算へ含める
  • `/cd`後もサンドボックス制限を保ち、権限変更後の古いGuardian判定を再利用しない
MCP連携で得たデータをそのままモデルへ渡さず、組織側でマスキングや検証を挟める。複数エージェントの費用集計と権限継承も、業務利用の監査性に直結する。

Slackbot、個人のスキルをチーム標準へ配る機能を強化

SlackはSlackbotに、社内データとWebを横断するDeep Research、最大25個のスキルを束ねるSkill Sets、全画面のBig Modeを追加した。スキルの社外共有、管理者向け利用状況ダッシュボード、定期タスク管理も同時に展開する。

キーポイント

  • Big Modeは調査、文章作成、分析、ファイル生成を全画面で扱う
  • Skill Setsは最大25個のスキルをまとめ、ユーザーグループやチャンネルへ配布できる
  • Deep ResearchはSlack内の情報と公開Webを統合し、出典付きレポートを作る
  • 別のSlack組織へスキルのコピー用リンクを共有できる
  • 管理者はスキルの利用状況と権限を一元管理できる
AI活用の差が、良いプロンプトを持つ個人から、良い業務手順を組織へ配れるチームへ移る。スキルの作成だけでなく、配布、更新、権限、利用状況までを一つの運用として設計しやすくなった。

Supabase、Linuxセルフホストの初期設定を1コマンドへ集約

SupabaseはLinux上のセルフホストを、セットアップスクリプト1本で始められるようにした。Dockerの導入、設定取得、URL入力、秘密鍵生成、イメージ取得までを自動化するが、バックアップや監視などの運用責任は利用者に残る。

キーポイント

  • Debian、Ubuntu、RHEL、CentOS、Fedoraをサポートする
  • `curl -fsSL https://supabase.link/setup.sh | sh`で初期化できる
  • Docker Engineと必要ツールを導入し、JWT鍵と管理画面パスワードを生成する
  • セルフホストではバックアップ、高可用性、監視、OS更新を利用者が担う
  • ローカル開発用CLIの構成を本番公開してはいけない
データの所在や閉域運用を理由にマネージド版を選べなかった組織でも、導入の入口は軽くなる。ただし、1コマンド化は運用責任を消さない。バックアップと更新計画を同時に作って初めて本番運用になる。

SonyとWarnerの音楽出版部門、Anthropicと共同創業者を提訴

キーポイント

〈知見〉AIで業務システムを作るなら「持ち続けるコスト」まで見る

AIコーディングで業務システムを短時間に作れても、認証、バックアップ、非同期処理、監視まで人が抱えれば自社開発の負担は残る。投稿者はCloudflare WorkersとTursoを軸に、Workflows、Queues、Durable Objects、Email Service、Zero Trustを組み合わせ、「作れる」から「持ち続けられる」へ進む構成を整理した。

キーポイント

  • Goodpatchでは185人が217個のアプリを作り、コード未経験者の86%がデプロイまで到達した
  • 年間約300万円を払っていたSaaSと同等の社内ツールを、Claude Codeで6〜7時間で作った事例がある
  • kubellでは非エンジニアが業務を自動化し、部署全体で月160時間を削減した
  • AIコーディングだけでは、DB、バックアップ、キュー、メール、認証、監視の負担は消えない
  • 自社固有の案件管理や見積はBuild、制度追随が必要な会計・給与・決済はBuyが向く
PoCで動くことと、現場が毎日使い続けられることは別の品質だ。BuildかBuyかは開発速度だけで決めず、制度変更への追随、自社固有の業務差、マネージドサービスへ寄せられる運用範囲の3点で判断したい。
