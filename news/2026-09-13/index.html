Claude Codeの評価・再開処理が改善

Claude Code 2.1.269は、プラグインの評価を再現可能な形で実行する機能と、VS Codeでサブエージェントの状態を確認する画面を追加しました。長いセッションの再開やキャッシュ利用も修正。翌12日の2.1.270では、読み取り専用のgitコマンドで余分な承認を求める不具合が修正されています。

キーポイント

  • プラグイン評価をJSON・HTMLで出力
  • VS Codeにエージェントの状態・停止・履歴表示
  • 2.1.270でgitの余分な承認要求を修正
作業手順をプラグインにまとめている人は、同じ評価を繰り返して改善を確かめられます。更新後は普段の作業と再開操作を一度試しておくと安心です。

Claudeの利用費とつまずきをチーム別に見る

AnthropicはClaude Enterprise向けにsmart reportsのベータ版を公開しました。最長28日間の会話記録から一部を分析し、仕事の種類、費用、繰り返すつまずき、共有Skillにできる手順をまとめます。個人の業績評価や雇用判断のための機能ではありません。

キーポイント

  • 対象はClaude Enterprise、初期設定はオフ
  • ベータ中は組織ごとに月10レポートまで無料
  • 個人・人事・健康・法務などの会話は分析から除外
利用回数だけでは、どの仕事が楽になったかは分かりません。費用の大きい作業や繰り返す失敗を見つけ、接続設定や共通手順の改善につなげられます。

Vercel Sandboxの実行地域が20か所に

Vercel Sandboxの対応地域が4か所から20か所へ広がりました。データベースなどに近い地域でAIのコード実行環境を作れます。ProとEnterpriseでは、作成できなかった場合に試す代替地域も指定できます。

キーポイント

  • 地域の選択は全プランで利用可能
  • 既定の地域はiad1のまま
  • 既存のSandboxは作成済みの地域に残る
処理のたびに離れた地域へ通信する構成では、待ち時間の短縮につながります。代替地域も含めて、データを扱ってよい場所と合わせて選べます。

GitHub Actionsのキャッシュ権限を選べる

GitHub Actionsに、キャッシュの読み書きをワークフローやジョブごとに制限するcache-modeが加わりました。全プランで一般提供され、読み取りのみ、読み書き、書き込みのみ、利用禁止の4種類を指定できます。

キーポイント

  • ジョブの設定がワークフローの設定に優先
  • 再利用先へ渡す権限は呼び出し元の範囲内
  • 低信頼イベントに書き込みを許すと警告
外部からの変更を検査する処理と、本番用の成果物を作る処理で、必要な権限を分けられます。設定を省略した場合は既存の安全な既定値が続きます。

〈知見〉AIで作ったアプリのアクセス権を試す

八木利生太郎氏はMoltbookの事例を題材に、AIで作ったアプリのアクセス制限などを確認する観点を紹介しています。元のWiz調査は2月2日公開で、最新の漏えい事件ではありません。Wizによると問題の中心はDB側の権限設定であり、Supabaseの公開用キーがブラウザにあること自体で危険と決まるわけではありません。

キーポイント

  • 2つのテストアカウントで他人のデータに届かないか確認
  • DBの行単位の権限で読み取り・書き込みの両方を検証
  • 秘密キーや認証トークンは公開用キーと区別して管理
ログイン画面が動くかに加えて、その人に許されたデータだけ扱えるかを確かめたいところです。AIへの指示に加え、実際のアクセス結果まで見ると確認漏れを減らせます。
