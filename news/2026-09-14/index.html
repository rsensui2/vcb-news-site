キーポイント

Copilotが修正済みのレビュー指摘を閉じる

GitHub Copilot code reviewは、修正を含むコミットを再レビューした際、解消した自分の指摘を自動で閉じるようになりました。提案を適用するときのコミット文も変更内容に合わせて作成します。内部の検査ではビルドやテストなどの道具を使い、Lite設定でも複数エージェントの結果をまとめます。

キーポイント

  • 再レビューで修正済みと判断した指摘を解決済みに
  • 未対応の指摘は開いたまま残す
  • ビルド・テストを含む検証手段を拡大
残った指摘を追いやすくなります。自動で閉じた項目も、差分やテスト結果と照らして確認しましょう。

VS Code Agentsの利用状況をCopilotで集計

GitHubのCopilot利用状況レポートに、VS Codeの専用Agentsウィンドウの利用人数、セッション数、ユーザーメッセージ数が加わりました。1日・28日単位で組織全体と利用者別に確認できます。通常のエディター内のAgent Modeとは別の集計です。

キーポイント

  • 専用Agentsウィンドウの活動が対象
  • 該当データがなければ項目なし、またはnull
  • 閲覧権限と利用状況計測ポリシーの有効化が必要
どのチームで使われているかを把握し、研修後の定着を確認できます。利用回数だけを成果とみなさず、手戻りや作業時間と合わせて見ると改善点を探しやすくなります。

TailscaleのAI接続は利用者のIDで管理

VercelはTailscaleのAI接続サービスApertureの構築事例を公開しました。Apertureは社内ネットワークの利用者IDとAIへのアクセスを結び付け、個々の社員やエージェントへAPIキーを配る負担を減らします。事例では、モデルへの接続をAI Gateway、コードの実行場所をSandboxに任せる構成が説明されています。

キーポイント

  • 利用者の追加・削除とAIアクセスを連動
  • モデルごとの費用と使用量を共通の接続口で取得
  • 実行用Sandboxもネットワーク上のIDで確認
人やAIが増えるたびに鍵を配る運用から、誰に何を許すかを管理する運用へ移せます。Aperture自体の新規発表ではなく、既存サービスの構築事例です。

Featuredは3人の開発チームで広報AIを運営

〈知見〉AIが直した手順を未使用の課題で試す

HarnessDevは、AIに実行手順や道具の使い方を含むハーネスを作らせ、その後の自己改良を調べた研究です。64回の版変更のうち、開発中の評価と未使用課題の評価が同じ方向へ動いたのは34回でした。この数字は改善成功率ではなく、2種類の評価の方向が一致した割合です。

キーポイント

  • 構築実験は6モデル・5ベンチマーク・2,207課題
  • 最終版が未使用課題でも最良だったのは9系列中2系列
  • 実行モデルを替えると改善の結果も変わる
手順をAIに直させたら、改善に使わなかった別の仕事でも試す必要があります。成功率と利用量を一緒に比較し、変更前へ戻せる版を残すと効果を確かめやすくなります。
