Copilotの自動選択で費用と品質の優先度を指定

GitHub Copilotのモデル自動選択に、費用重視のEfficiency、均衡を取るBalance、品質重視のIntelligenceが加わりました。どの設定でも候補モデルは共通で、依頼の内容に応じて選びます。品質重視でも、簡単な依頼には小さなモデルを使う場合があります。

キーポイント

  • VS Code、Copilot CLI、Copilot appへ順次提供
  • 費用・品質・応答時間の優先度を選択
  • 料金は実際に選ばれたモデルに基づく
  • 有料プランの自動選択には引き続き10%割引
普段の修正と難しい設計で、AIに求める水準を切り替えやすくなります。同じ作業で結果と費用を比べ、自分の用途に合う設定を探せます。

Gemini 3.8 Liveで会話中も推論とツールを実行

キーポイント

  • AI SDKのrealtime APIから接続

音声で依頼を受け、調べ物の途中にも応答するアプリを作る選択肢です。試作では答えの正しさに加え、待ち時間の伝え方や割り込み時の挙動も確かめたいところです。

Claude Code 2.1.273で子エージェントの結果通知を修正

Claude Code 2.1.273は、子エージェントの最終応答に利用量やモデルIDがない場合、失敗扱いとなって結果が届かない不具合を修正しました。途中でバックグラウンドへ移した子エージェントの残りのメッセージが、SDKなどの出力から抜ける問題にも対応しています。権限判定や管理者設定の適用に関する修正も含まれます。

キーポイント

  • 子エージェントの完了結果が欠落する条件を修正
  • 文脈量の二重計上による早すぎる圧縮を修正
  • MCP接続の自動復旧を断念した際に通知
長い作業をAIへ任せる場合、処理の完了と結果の受け取りを分けて確認する必要があります。結果が来ない、会話が早く圧縮されるといった症状の切り分けに使える更新です。

AI SDKが対応エージェントのサブスク認証を利用

複数のコーディングエージェントを同じ呼び出し方で動かすAI SDKのharness層が、各エージェントのサブスクリプション認証に対応しました。対応する実行環境では、ホスト側にある認証情報を利用します。明示したAPI認証情報が優先され、ai-gatewayモードではサブスク認証を読みません。

キーポイント

  • directモードは明示した認証情報がなければサブスクを参照
  • autoモードはGateway認証情報がない場合に同様に動作
  • 実際のトークンはホスト側で管理・更新
既存の契約を使ってエージェントを組み込む選択肢が増えます。利用できる認証方式は各エージェントに依存するため、接続確認と利用量の確認をセットで行いましょう。

Ollama 0.34.1でMacのモデル作成と一覧取得を改善

Ollama 0.34.1では、MLX形式のsafetensorsからモデルを作る機能が実験扱いを外れました。Apple Siliconのメモリ処理や、大きなモデル一覧の取得も改善しています。一方、GGUFモデルの作成では、safetensorsの変換と量子化にllama.cppのツールを使う方式へ変わりました。

キーポイント

  • MLXモデル作成の実験扱いを終了
  • 開発側の一覧取得テストは3.1秒から294ミリ秒へ短縮
  • 同じトークンの繰り返し検出を100回に変更
  • 新規モデルではtypical_pを設定できなくなった
MacでローカルAIを運用する人は、モデルの読み込みだけでなく作成手順も確認したい更新です。速度の数値は開発側の条件での測定であり、自分のモデル数や端末で再確認が必要です。

GitHubの企業共通セキュリティ設定を組織管理者にも適用

GitHub Advanced Securityの設定を、企業内の組織管理者も上書きできないように固定できるようになりました。従来の適用対象はリポジトリ所有者まででした。企業の管理者は、設定を固定しない、リポジトリ所有者まで固定、組織所有者まで固定の3通りから選べます。

キーポイント

  • 企業レベルの設定を組織全体へ適用
  • 組織・リポジトリ管理者による上書きを防止
  • Enforcement欄で適用範囲を選択
チームごとに設定が変わり、共通の検査が外れる事態を防ぐための機能です。管理を一元化する場合は、変更を受け付ける担当と手順も決めておくと運用しやすくなります。
