Claude Code 2.1.283、企業向けモデル制御と指示書監査

Claude Code 2.1.283では、組織が利用できるモデルをバージョン単位で固定する設定が加わった。古いモデル向けの指示が残っていないか、CLAUDE.mdやSkillsを調べる`/doctor prompt-audit`も使える。

キーポイント

  • `availableModelsMatch: "exact"`で一覧にない新しいモデルを自動的にブロック
  • `deniedModels`で許可済みの一覧から個別のモデルを除外できる
  • `/doctor prompt-audit`が指示書、Skills、agents、commandsを点検
  • `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`で同一プロンプトのリクエストを識別できる
企業でモデル更新を管理しつつ、古い指示が新モデルの動きを妨げていないか点検しやすくなる。

Vercel Sandboxのメモリ使用量を可視化

Vercel Sandboxの観測画面とCLIにメモリ使用量が加わった。平均値とP75・P95を確認でき、メモリ上限に近づくSandboxを探せる。

キーポイント

  • ダッシュボードのMemory Usageカードは平均、P75、P95を表示
  • 詳細グラフには上限の85%を示す破線が入る
  • Observabilityの`memoryUsedBytes`からクエリやアラートを作れる
  • CLIの`vercel metrics`では`vercel.sandbox.memory_used_bytes`を取得できる
ビルドやエージェントの実行がメモリ不足で落ちる前に、負荷の偏りを見つけやすい。

GitHub ActionsからVercelレジストリへOIDCでpush

`vercel/vcr-action/login`を使うと、GitHub ActionsからVercel Container RegistryへOIDCでログインできる。ジョブ終了時には短命のトークンを失効させるため、長期のレジストリ認証情報を保存せずに済む。

キーポイント

  • Vercelチーム側にリポジトリとワークフローに合うOIDCポリシーが必要
  • GitHub Actionsのジョブに`id-token: write`を付ける
  • 既定はDocker認証で、PodmanとBuildahも選べる
  • 作成したlinux/amd64イメージは同一プロジェクトのSandbox用カスタムイメージにも使える
CIで長期シークレットを管理する手間を減らせる。導入にはVercel側の権限設定が要る。

Vercel AI GatewayにPixel Canaryを期間限定で無料提供

Vercel AI Gatewayにコーディング向けモデル`stealth/pixel-canary`が加わった。フロントエンドやモバイルUIの実装向けで、stealth期間中は無料で試せる。

キーポイント

  • Vercel公表のNext.js評価では31問中28問を通過し、成功率は90.3%
  • AGENTS.mdでNext.js文書を与えた条件では31問中30問を通過
  • 評価は最大4回の試行のいずれかが成功すれば合格とするpass@4
  • ZDRに非対応で、送信内容が学習や改善に使われる可能性がある
UI実装向けモデルを比較する選択肢になる。無料期間とデータ利用条件を確認してから試したい。

SupabaseのPostgreSQL更新、一部拡張は事前確認が必要

SupabaseはPostgreSQL 15.19と17.11への更新を発表した。44件のCVEへの対応を含む一方、ltree、pgcrypto、btree_gist、独自演算子を使う環境には確認が必要な場合がある。

キーポイント

  • 9月28日から新規プロジェクトには新版を適用し、既存プロジェクトはダッシュボードから更新できる
  • マルチバイトやICUのltreeインデックスは再作成が必要な場合がある
  • 旧暗号方式で保存したpgcryptoのデータは既定で復号できなくなる
  • 公式記事の検出クエリが何も返さなければ対応は不要
マイナー更新でも拡張の利用状況次第で影響が出る。アップグレード前に公式の検出クエリで対象を確かめたい。

Copilot利用指標APIがPRレビューの待ち時間を3段階に分解

GitHub Copilotの企業・組織向け利用指標APIに、プルリクエストのレビュー所要時間が加わった。初回レビューまで、初回から最終レビューまで、最終レビューからマージまでの中央値と90パーセンタイルを見られる。

キーポイント

  • `repos-1-day`の`pull_request_review_times`配列で提供
  • 対象は人が作り、別の人がレビューしたPR
  • BotやCopilot code reviewによるレビューは時間計測の対象外
  • 過去分の補完はなく、対象マージがない日は空配列になる
レビューの遅れが初動、やり取り、承認後のどこにあるか分けて改善できる。

Cloudflare Workersのtracingに例外記録とスパン操作を追加

Cloudflare WorkersのカスタムスパンAPIに`startSpan`、`getActiveSpan`、`recordException`などが加わった。既存のトレースへ属性や例外を残す実装がしやすくなる。

キーポイント

  • `startSpan(name)`はスパンを作るがアクティブにはしない
  • `getActiveSpan()`は現在のスパンを返し、カスタムスパン外ではルートスパンを返す
  • `recordException()`はError、文字列、所定の項目を持つオブジェクトを受け取る
  • `setAttributes()`は複数属性を設定し、チェーン可能なスパンを返す
本番障害時に、処理の区間と例外を同じトレースで追いやすくなる。

Opus 5.5で動画を作るなら絵コンテと実製品素材を先に渡す

Rexan Wong氏は、Opus 5.5でモーショングラフィックを作る手順を投稿した。参考映像、ブランド素材、実製品の画面を渡して絵コンテを3案作り、各シーンの静止画を確認してから動きを付けるという制作例だ。

キーポイント

  • 参考動画を1〜2本選び、映像のテンポと画面転換を示す
  • HyperFramesかRemotionで各シーンをコード化してレンダリングする
  • ブランド素材と実製品の画面を渡して絵コンテを3案作る
  • 静止画の段階でシーンを直し、完成後はカメラ操作を具体的に指示する
モデル任せの一発生成より、素材と検品の順番を決めた制作手順が参考になる。投稿者の経験談であり、モデルの一般的な性能評価ではない。
