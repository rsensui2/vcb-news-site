Supabase Logsは計測を開始、課金は2027年初まで猶予

Supabaseのログ生成量と読取量が使用量画面で計測されるようになった。現時点では制限を強制せず、課金開始も2027年初まで猶予がある。

キーポイント

  • 90%超のプロジェクトは含有枠内
  • Logs Ingestは生成データ量で、超過分が課金対象
  • Logs Queryは読取スキャン量で、直接の課金対象ではない
  • Postgresのログ設定で生成量を調整できる
猶予中に使用量を見て、必要なら記録するログの量を調整できる。

GitHub Issuesで個人用ビューと関連Issueの連携が拡充

GitHubのリポジトリIssuesページで、個人だけが使う保存ビューに対応した。「Relates to」関係はAPI、webhook、検索にも対応し、一般提供となった。

  • Issues検索とProjects検索でも関連を扱える
自分用の絞り込みを保存しつつ、関連Issueを自動化から追いやすくなる。

Copilotの企業設定を画面上で検証可能に

GitHub Copilotの企業向けmanaged settingsに製品内バリデータが加わった。JSONの構文やチーム対応付けの誤りを、影響するファイルとJSON path付きで確認できる。

キーポイント

  • 不正なJSONと未対応設定を検出
  • 無効なチームマッピングも検出
  • 対象はmanaged-settings.jsonとteam-mappings.jsonなど
  • 修正後は.github-privateの既定ブランチへ反映して再確認
企業ポリシーが適用されない設定ミスを見つけやすくなる。

Cloudflare Workersの指標に段階デプロイを重ねて表示

Cloudflare WorkersのMetricsチャートに、リリースと段階デプロイの履歴が重なるようになった。エラーやCPU時間の変化を、どの版に何割のトラフィックを流したかと照合できる。

キーポイント

  • 段階デプロイは一つの帯として表示
  • ホバーで旧版・新版、所要時間、配分率を確認
  • ロールバックは別のリリースとして表示
  • アップロードだけの版や0%の版は表示されない
不具合が始まった配分段階を画面上で特定しやすい。

Browser Runのクロール完了をQueuesで受け取れる

Cloudflare Browser Runのクロールジョブが、開始・更新・完了イベントをQueuesに送れるようになった。処理の進捗確認や後続処理の起動を、繰り返しの状態照会なしに組める。

キーポイント

  • イベントはcrawl.started、crawl.updated、crawl.finished
  • 購読はアカウント単位
  • Wranglerのqueues subscription createで設定
  • イベント本文にはジョブIDや状態が含まれる
クロール完了後の取り込み処理をイベントで起動できる。

Email Sendingの配信停止を送信ドメインごとに管理

Cloudflare Email Sendingのサプレッションに適用範囲が加わった。バウンスや苦情による自動サプレッションは送信ドメイン単位となり、別の送信ドメインへ波及しにくくなった。

キーポイント

  • accountはアカウント全体に適用
  • sending_domainは指定した送信ドメインだけに適用
  • APIでscopeを省略すると従来どおりaccount
  • 一覧APIではscope_typeとscope_valueで絞れる
複数ブランドのメール運用で、一つのドメインの問題が他の配信を止める範囲を抑えられる。

Claude Codeのeffortは実装と検証で使い分ける

Claude Code開発者のThariq氏は、effortを変えて同じ課題を試した結果を長文記事で公開した。通常の実装はlow・mediumで対話し、例外条件が多い検証やセキュリティではhighを使う運用を提案している。

キーポイント

  • 高いeffortでは検証と例外条件の確認が増えたという観察
  • HTMLサニタイザーの例ではlowが5回中1回、xhighが5回中5回成功
  • effortを上げても方針そのものの誤りは解消しない
  • 開発者自身は実装と検証で水準を切り替える
作業ごとに時間と検証の深さを変える判断材料になる。
