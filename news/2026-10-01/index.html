Next.js、9月のセキュリティ修正を公開

Next.jsは9月のセキュリティリリースとして、16.3.8（Active LTS）と15.5.27（Maintenance LTS）を公開した。先週予告した修正のうち、依存先の遅れで延期していた分も含め、画像最適化のSSRFなど7件の脆弱性に対応している。

キーポイント

  • 画像最適化のSSRF（High、CVE-2026-94483）は images.remotePatterns 未設定なら対象外
  • 自己ホスト環境のSSG・ISRでページのキャッシュが別ルートの内容に置き換わる問題（Medium）
  • use cache の入れ子やDraft Modeで、本来見せない内容が混ざる問題（Medium）
  • next dev のMCPエンドポイントからの情報漏えい（Low、本番は対象外）
  • npm install next@16.3.8 または next@15.5.27 で更新
Next.jsで作ったアプリは、デプロイ先を問わずまず版数を確認して更新したい。自己ホストかVercelか、webpackかTurbopackかで影響が変わる項目があるため、自分の構成と照らして読む必要がある。

GPT-6.1 SolがGitHub Copilotで一般提供

GitHubはOpenAIのGPT-6.1 SolをCopilotで一般提供し、段階的に展開を始めた。エージェント型のコーディングやターミナル作業向けで、GitHubの初期検証ではGPT-6やGPT-5.6系より少ないトークンと手順で作業を終えたという。

キーポイント

  • 対象はCopilot Pro+、Max、Business、Enterprise
  • VS Code、Copilot CLI、coding agent、JetBrains、Xcodeなどのモデル選択で利用可能
  • 料金は提供元の定価に基づく従量課金
  • Business・Enterpriseは管理者がモデルポリシーで利用可否を制御
Copilotで選べるコーディング向けモデルが増え、Claude系モデルと費用や手数を比べやすくなる。ベンチマークの数値は計測環境で大きく変わるため、自分の作業で試して判断したい。

Claude Code、WebFetch停止と利用先制限に対応

Claude Code 2.1.285が公開された。環境変数でWebFetchツールを無効にできるようになり、管理設定 allowedProviders で端末が使えるAPIの提供元を制限できるようになった。

キーポイント

  • CLAUDE_CODE_DISABLE_WEB_FETCH でWebFetchを停止
  • allowedProviders でAnthropic API、Bedrock、Vertex AIなど利用先を限定（管理設定）
  • claude --desktop で現在のディレクトリや既存セッションをデスクトップアプリで開ける
  • claude plugin configure でプラグインの設定項目を確認・保存
会社や研修の環境で、外部Webの取得や契約外のAPI利用を端末単位で止めやすくなる。管理者が配る設定で縛れる点が、個人設定との違いになる。

Cloudflare Sandbox SDKが1.0に

CloudflareはSandbox SDK 1.0を公開した。自分で書いたDurable Objectのクラスから、this.ctx.container を通じて各サンドボックスのコンテナを直接制御する形になった。

キーポイント

  • 起動ごとにイメージとインスタンスサイズを選べ、デプロイで実行中のサンドボックスは再起動しない
  • ファイルをスナップショットとして保存し、そこから起動できる（public beta）
  • 外向き通信をWorker側で処理し、認証情報をサンドボックスに渡さない
  • 0.xは2026年12月31日まで修正を継続。新方式への切り替えデプロイは一方向
AIエージェントにコードを実行させる環境を、起動・停止・保存まで自分のコードで管理できる。0.xから移る場合は、戻せない手順があるため移行ガイドで予行演習してから進めたい。

Copilotの複数モデル協調がVS Codeでも利用可能に

GitHubは、複数のモデルを組み合わせて作業するHydraFusionの研究プレビューを、Copilot CLIに加えてVS CodeとGitHub Copilotアプリでも使えるようにした。モデル選択の一覧に表示されるが、単一のモデルではなく作業の進め方ごと選ぶ仕組みだ。

キーポイント

  • Single：1つのモデルがそのまま解く
  • Cascade：軽いモデルの下書きを品質基準で判定し、足りなければ強いモデルへ回す
  • Critique：別系統のモデルがレビューし、下書きしたモデルが1回直す
  • VS Code 1.140以降、対象はPro、Pro+、Business、Enterprise
「下書きと別モデルによるレビュー」を人が手で組まなくても試せる。研究プレビューのため、仕様が変わる前提で使いたい。

Opus 5.5の動画制作は周辺の仕組みで決まる

Movez氏は、Opus 5.5でコードから動画を作る方法を12段階にまとめた長文記事を公開した。モデルが書くのは動画ではなく任意の時刻の画面を描くプログラムで、品質の9割はプロンプト以外の仕組みで決まると整理している。

キーポイント

  • seek(t) 関数で各フレームを描き、ヘッドレスブラウザとffmpegで書き出す
  • 好きな動画の1フレームなど参照を渡すと、平凡な既定の見た目から抜け出せる
  • 雰囲気ではなく、場面ごとの状態を並べた仕様を書く
  • 書き出した静止画をモデル自身に採点させ、上位3つの問題を直す流れを繰り返す
  • 固まった手順はSkillにまとめ、次からは1文で呼び出す
「プロンプト1つで作った」と言われる作品の裏には、参照素材や確認の繰り返しがある。動画に限らず、AIに成果物を作らせるときの段取りとして応用できる。
