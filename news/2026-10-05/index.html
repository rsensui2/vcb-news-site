SupabaseとTurso、エージェントごとのDBを目指す

SupabaseはTursoの買収を発表しました。小さく素早く作れるデータベースを各エージェントに割り当て、アプリの成長に応じてPostgresへ進める構想です。

キーポイント

  • 既存ユーザーの利用方法は変更なし
  • SupabaseはPostgres、TursoはSQLiteの開発を継続
  • 試作から本番へ同じ開発体験を目指す
AIが試作を大量に作ると、データの置き場所も増えます。タスクごとに分けて保管し、必要なアプリだけ本番へ育てる設計の参考になります。

Claude Code 2.1.289、権限ルールの不具合を修正

Claude Code 2.1.289では、拡張機能の承認やシンボリックリンク経由の参照で権限ルールが効かない不具合が修正されています。画面描画やプラグイン更新に関する修正も含まれます。

キーポイント

  • 管理対象端末で複合コマンドのdeny・askを修正
  • IDEからリンク経由で参照したファイルのRead制限を修正
  • 端末のフリーズや拡張機能の表示不具合にも対処
Claude Codeに拡張機能を入れているチームは更新内容を確認したいところです。更新後に禁止・確認ルールが意図どおり働くかを試すと、運用上の見落としを減らせます。

GitHub Appのトークンが約520文字に

GitHub Appのインストール用トークンは、新規発行分が約520文字の形式へ切り替わりました。従来の40文字を前提としたチェックや保存欄は、連携の失敗につながる可能性があります。

キーポイント

  • ghs_で始まる形式は維持
  • 権限・対象リポジトリ・1時間の有効期限は変わらない
  • 試験用ヘッダーは11月30日に廃止予定
GitHub連携が急に動かなくなったら、トークンを短く切っていないか確認しましょう。文字数チェック、保存先、ログの秘密情報を隠すルールが点検箇所です。

GitHubの脆弱性報告に非公開コメント

GitHubでは、非公開の脆弱性報告を有効にした公開リポジトリで、書き込み権限を持つ人だけが読めるコメントを投稿できるようになりました。書き込み権限を持たない報告者に見せない調査メモも、セキュリティアドバイザリの履歴に残せます。

キーポイント

  • 非公開の脆弱性報告を有効にした公開リポジトリが対象
  • 閲覧権限は現在のリポジトリ権限に従う
  • 投稿後に通常コメントへ変更できない
脆弱性の対応中に、調査や調整のメモを別の場所へ移す手間が減ります。投稿前に公開範囲を選ぶことが必要です。
