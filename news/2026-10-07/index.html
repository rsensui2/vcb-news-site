Beam、コードと推論を担う公開モデルを予告

Reflectionは、コード作成や推論に向けた最初のモデルBeamを紹介しました。現在は最終評価と一部利用者への先行提供の段階で、重みは今月中にApache 2.0で公開する予定です。

キーポイント

  • 重み・技術報告・評価と追加学習の道具を公開予定
公開後に、自社の開発課題で精度と実行費用を調べる材料になります。性能や効率の数値は提供元の説明で、通常のPCで動くことを意味しません。

Claude Code 2.1.292、委任時の思考量を指定

Claude Code 2.1.292は、Agentツールにeffort引数を追加しました。子エージェントへ頼む仕事ごとに思考量を指定でき、プラグイン導入や再開・定期実行の不具合修正も含みます。

キーポイント

  • プラグイン導入時にマーケットプレイスを指定可能
  • 再開後の定期タスクやバックグラウンドのループを修正
  • ファイル参照・管理設定に関する権限制御も修正
短い調査と難しい設計で、委任先の思考量を分ける選択肢が増えます。定期実行を使う人は、更新後に再開と次回実行が正常に動くか確認したいところです。

AI Gateway、不確かな判断だけ別モデルへ

Vercel AI Gatewayは、判断モデルの回答が指定した確信度の条件に触れたとき、別モデルへ判断を回す機能をベータ公開しました。従来のエラー発生時の切り替えは、そのまま使えます。

キーポイント

  • Choice・Scoreは確信度、Booleanは確率の範囲を条件にする
  • 複数の条件を組み合わせられる
  • 切り替えた場合は両段階の処理が課金対象
問い合わせの振り分けなどで、判断が難しい入力だけ追加の処理へ回せます。確信度は正しさの保証ではないため、実際の入力と正解で条件を調整する必要があります。

GitHub、LovableとSupabaseの秘密情報を検出

キーポイント

  • LovableのAPIキーを追加
  • PydanticのLogfireとAI Gatewayのキーを追加
  • SupabaseのOAuthと権限を絞った個人トークンを追加
AIで作ったアプリのコードに、接続用のキーを残してしまう事故の発見に役立ちます。自分のリポジトリで検出と通知が有効かを確認し、警告が出たキーは失効・再発行しましょう。

GPT-6 AstraとSol、サブスク経由の速度を改善

OpenAIのTiboは、サブスクリプション経由のGPT-6 AstraとGPT-6.1 Solの標準速度を約50%高速化したと報告しました。Sign in with ChatGPTを使う提携製品も対象で、利用者の設定変更は不要としています。

キーポイント

  • OpenCode・Pi・Amp・Devinなどを対象として例示
  • 返信では毎秒30から50トークンへの変化を説明
  • API全体の速度改善を約束した発表ではない
AIへ頼む作業の待ち時間が減る可能性があります。約50%という数字は提供元の説明で、ツール操作やテストまで含む仕事全体が同じ割合で速くなるとは限りません。
