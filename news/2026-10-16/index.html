GitHub AI Scan、PRの差分から脆弱性を検出

GitHubがAI Scan for pull requestsを一般提供しました。PHP、Shell/Bash、Terraformなど、CodeQLで十分に扱えない言語や構成の変更を調べ、PR上にリスクの説明や修正案を表示します。所見は助言扱いで、チェックを失敗させたりマージを止めたりする機能ではありません。

キーポイント

  • CodeQLの対象外を含むPR差分を検査
  • 所見は助言。マージを自動では止めない
  • フォークとDependabotのPRは対象外
  • 非公開・internalではCode Security等が必要
  • Code Security AI Creditsを消費。Copilot契約は不要
AIが書いた設定ファイルも、レビュー前の確認にかけやすくなります。検出結果を誰が確認し、どこで修正を必須にするかは、チーム側で決める必要があります。

Agentic autofix、修正を検証してドラフトPRへ

GitHubのAgentic autofixが一般提供になり、アラートの調査、修正案の作成、CodeQLでの再検査を経てドラフトPRを開けるようになりました。10月15日の発表ではGitHub Enterprise CloudのCode Security／Advanced Security利用者を対象としています。既定ブランチのアラートを最大25件まとめて依頼でき、管理者の有効化と課金設定が必要です。

キーポイント

  • 関連ファイルの調査からCodeQL再検査まで実行
  • 既定ブランチのアラートが対象
  • 最大25件を1本のドラフトPRにまとめる
  • Code Security AI CreditsとActions分を消費
  • 生成された変更は人がレビュー・テストする
検知した問題を修正候補にするまでの作業を任せられます。AI Scanによる検出とは別の機能で、修正後の安全性や動作はPRのレビューでも確認します。

Vercel Daemons、常駐ワーカーをベータ提供

Vercel Daemonsのパブリックベータが始まりました。HTTPサーバーを用意せず、キューなどから仕事を取り続けるコンテナをアプリと同じプロジェクトに配置できます。リージョンごとに指定した台数を維持し、プロセス終了やクラッシュ時には再起動します。

キーポイント

  • Celery・BullMQ・Kafkaなどのワーカーに対応
  • リージョンごとの台数を指定
  • 終了・クラッシュ時にインスタンスを再起動
  • ベータでは自動増減・永続ストレージに未対応
  • プレビュー環境へのデプロイは未対応
Webアプリと裏側のワーカーを同じ基盤で運用する選択肢が増えます。再起動で同じ仕事を重複処理しない仕組みと、外部に状態を保存する設計を合わせて考えられます。

Vercel Drives、Sandboxのファイルを永続化

Vercel Sandbox向けの永続ストレージVercel Drivesが、Hobby・Pro・Enterpriseで一般提供になりました。ディレクトリとしてマウントしたファイルはSandbox停止後も残り、次の実行や別のSandboxから利用できます。forkで独立して書き込めるコピーを作り、並列ワーカーの変更を分離することもできます。

キーポイント

  • Sandbox停止後もファイルを保存
  • 別Sandboxから同じDriveをマウント可能
  • forkしたDriveの変更は相互に干渉しない
  • Hobby・Pro・Enterpriseで一般提供
AIの作業ファイルやデータセットを、実行のたびに準備し直す手間を減らせます。Daemonsの永続ストレージ対応とは別で、今回の対象はSandboxです。

Codex 0.163.0、応答中でも指示を変更

Codexの安定版0.163.0が公開されました。応答中に追加の指示を送って方針を変えられ、割り込み時には実行中のCode Modeとその配下のツール呼び出しも停止します。設定を横断検索して変更する/configや、独立した読み取り専用ツールの並列実行も加わりました。

キーポイント

  • /configで設定を検索・変更
  • 応答中の追加指示を即座に反映
  • 割り込み時は配下のツール呼び出しも停止
  • /daemonから管理対象サーバーを再起動
  • 保存した会話の再開時に権限設定を復元
調査を待ってから指示を出し直す手間が減ります。外部ツールで既に完了した操作まで取り消す機能ではないため、途中で方針を変えた際も結果を確認して続けます。

Cloudflare Gateway、許可通信をWorkersへ

Cloudflare GatewayとWorkersの連携が、全Zero Trustプランでパブリックベータになりました。HTTPポリシーのForwardに一致した許可済み通信で、自作のWorkerを実行できます。リクエストや応答の変換、案内ページの返却、通知などを、別のプロキシを運用せず組み込めます。

キーポイント

  • 全Zero Trustプランのパブリックベータ
  • Forwardアクションで自作Workerを実行
  • ユーザー情報などGatewayの文脈を受け取る
  • 最終応答もGatewayが検査
  • 本文検査のBlockでWorkerが中断される場合あり
社内の通信ルールに応じた案内や記録をコードで追加できます。認証情報や通信内容をどこまで処理するかを決めてから、小さな対象範囲で試しやすくなります。

〈知見〉Anthropic、巨大モノレポをScionへ

Anthropicは自社の巨大モノレポを、内製の版管理システムScionへ5か月で移行した経緯を公開しました。同社によると、1日あたりのマージは5月の約2,500件から9月の3万件超に増加しています。常時オンラインのエージェントを前提に処理をサーバーへ寄せ、CIのチェックアウト高速化とインフラ縮小を実現したと説明しています。

キーポイント

  • 原文10月13日公開、15日追記の技術事例
  • 常時オンライン・サーバー中心の設計
  • 同社公表でCPU・メモリの規模が約200分の1
  • 7人で版管理・レビュー基盤などを構築
  • 一般向けのGit代替としての公開予定はない
AIで変更を作る速度が上がると、レビューやCIが次の制約になります。自分の開発でも、生成量を増やす前に待ち時間が集中する工程を測る材料になります。
