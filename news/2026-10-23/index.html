OpenAI、判定だけ返すAPIを一般提供

OpenAIは、文章を生成する代わりに「条件に当てはまる確率」「決まった選択肢のどれか」「採点基準に沿ったスコア」だけを返すDecisions APIを一般提供にしました。パブリックベータからの切り替えで、OpenAIはResponses APIより約10倍速いとしています。問い合わせの分類、リクエストの振り分け、作業の優先順位づけなど、アプリの中で次の動きを決める場面に向けた仕組みです。

キーポイント

  • エンドポイントは POST /v1/decisions、対応モデルは現在 gpt-6-luna のみ
  • 答えの型は3種類：確率（predicate）、選択肢（choice）、順序付きの採点（score）
  • 1リクエストで最大400問まで（ベータ時は200問）
  • ベータ以降、プロンプトキャッシュ、JSON入力、問いごとの画像、会話履歴とツール呼び出し結果の評価に対応
  • 音声のGPT-Liveから直接呼び出せるほか、Private Linkと組織単位の利用量レポートにも対応
  • 自由な形式のJSONを作るなら従来どおりStructured Outputs、ツール呼び出しはfunction callingを使うよう案内
エージェントの分岐の判断に、毎回フルの文章生成を使わずに済みます。自前で作っていた分類器や、LLMに「AかBか答えて」と頼んでいた処理を、速く安く置き換える候補になります。

Claude Platform、Google Cloudで全機能

Anthropicは「Claude Models on Google Cloud（Anthropic managed）」を一般提供にしました。Google Cloudの利用者が、Anthropic本家のClaude APIと同じ機能一式を、Google CloudのIAM認証のまま使えます。新機能やベータは本家と同じ日に使えるようになり、請求はGoogle Cloudの請求書にまとまり、既存のGoogle Cloudの利用コミットからも差し引かれます。

キーポイント

  • Claude Managed Agents（ベータ）、コード実行、Computer use、Agent Skills、Files API、Web検索・取得、MCPコネクタ（ベータ）、プロンプトキャッシュ、バッチ処理を利用可能
  • Claude Opus 5.5のFast Modeも一般提供。出力は最大2.5倍速く、料金は100万トークンあたり入力8ドル・出力40ドル
  • 使えるモデルはClaude Fable 5.1、Opus 5.5、Sonnet 5.5、Haiku 5.5。新モデルも発表と同時に追加
  • エンドポイントは現在USとGlobal。開発環境のClaude Consoleも使える
  • データ処理者はAnthropic。Googleがデータ処理者になる従来の「Google managed」も併存し、地域内のデータ保管やModel Armorなどが必要ならこちらを推奨
  • 既存の割引がある場合は、使い始める前にAnthropicかGoogle Cloudの担当者へ連絡するよう案内（さかのぼって適用されない）
Google Cloud中心の会社でも、Claudeの最新機能を遅れなく使えるようになります。今週発表されたOpenAIのモデルのGoogle Cloud提供に続き、AI各社がクラウドの垣根を越えて提供先を広げています。

Ollama、コーディング用Flintに対応

Ollama 0.40.8で、Recursiveのコーディングエージェント向けモデル「Flint」を ollama run flint で手元で動かせるようになりました。Flintは総パラメータ約40Bのうち、1トークンごとに動くのは約2.5Bだけの混合エキスパート（MoE）構成で、Apache 2.0ライセンスで重みが公開されています。知らないコードの読解、バグの追跡、機能の実装、テストの追加といった、リポジトリ全体にまたがる作業を想定しています。

キーポイント

  • 総パラメータ39.8B、アクティブ約2.5B。256個の専門家から1トークンごとに6個を選ぶ構成
  • 文脈長は262,144トークン。推論と複数回のツール呼び出しに対応し、OpenAI互換のツール呼び出しが使える
  • Recursiveの評価ではTerminal-Bench 2.1で54.9%、SWE-bench Verifiedで74.2%（自社測定）
  • Ollama 0.40.8での対応は現時点でmacOSのみ。ほかのGPUは次のリリースで対応予定
  • Hugging FaceにはBF16版（約80GB）とSGLang用の配信キットがあり、NVIDIA・Apple Silicon向けの量子化版は別に用意
動く部分が小さいので、Macでもコーディングエージェント用のモデルを手元で試しやすくなります。コードを外に出せない環境で、ローカルLLMでエージェントを回したい人の選択肢が増えました。

Claude Code、新API版への移行コマンド

Claude Code 2.1.307で、/claude-api api-version が加わりました。手元のコードを、今週公開されたClaude APIの新しいバージョン「2026-10-21」に合わせて書き換えるためのコマンドです。あわせて、権限ルールやauto mode、サンドボックスなどがツール呼び出しを止めたり確認を求めたりするたびに、OpenTelemetryのイベントを出すようになりました。

キーポイント

  • /claude-api api-version で、Claude APIのバージョン2026-10-21への移行を支援
  • OpenTelemetryに claude_code.safety_event を追加。権限ルール、auto mode、安全チェック、フック、サンドボックスが止めた・確認した・差し戻した操作を記録
  • 接続が途中で切れるとHTTPのMCPツールが2回実行される問題を修正。今後は読み取り専用など、繰り返しても安全なツールだけ再試行
  • macOSやLinuxがスリープした際に、MCPサーバーが失敗のまま残る問題を修正
  • 読めない形のツール呼び出しは、ターンを終える前に最大2回まで自動でやり直す
  • 同時に起動したforkサブエージェントが、互いの作業に手を出しにくくなった
temperatureの廃止などを含むAPIの破壊的変更への対応を、Claude Code自身に任せられます。MCPツールの二重実行の修正は、書き込みや送信をするツールを使う人にとって、実害を防ぐ変更です。

〈知見〉サブエージェントは増やしすぎない

AnthropicのApplied AIチームが、企業向けのエージェントでは、ルーターやプランナー、分野別のサブエージェントをメインのエージェントループにまとめたほうが良い場合が多い、という知見と移行の手順を公開しました。複数の企業導入を比べたところ、スキルを持たせた単一のエージェントが、何でも1つのプロンプトに詰め込む設計にも、サブエージェントに分ける設計にも、品質で勝つことが多かったとしています。費用と応答時間も下がりがちでした。

キーポイント

  • スキル（必要なときだけ読み込む手順書）とツール検索で、文脈とツールを少しずつ開示するのが基本の形
  • チームごとにサブエージェントを作ると組織図の写しになり、文脈の受け渡しで情報が落ちる、似たサブエージェントが乱立する、各チームが一文ずつ足したプロンプトが矛盾する、といった問題が起きる
  • ある企業の比較では、単一ループのほうが複数エージェント構成よりおよそ2倍速く動いた
  • 多くの用途は「明確なシステムプロンプト1つ、薄いデータ取得ツール4〜5個、厳しい出力ガードレール」で足りるという指摘
  • サブエージェントが向くのは、文脈の膨張で性能が落ちるとき、使い捨ての文脈で並列に作業したいとき、ツール選択や指示の衝突に悩むとき
  • 移行の判断を手順に沿って進めるキットとデモも公開
「とりあえずマルチエージェント」にしがちな設計を見直す材料になります。サブエージェントは不要だと言っているのではなく、文脈で仕事を区切れる場面に絞って使う、という整理です。

Cloudflare MCP、旧方式の/sseを廃止

Cloudflareが製品ごとに提供しているMCPサーバーが、/mcp だけを受け付けるようになりました。旧方式の /sse に接続すると「410 Gone」が返り、そのエラーの中に新しい /mcp のURLが示されます。MCPクライアントに /sse のURLを登録している場合は、書き換えが必要です。

キーポイント

  • /sse へのリクエストは410 Goneを返し、正しい /mcp のURLを案内する
  • 設定を /mcp に変えれば引き続き使える（例：https://docs.mcp.cloudflare.com/mcp）
  • /sse 経由でサインインしていた場合は、もう一度サインインを求められる
  • すでに /mcp を使っている接続には影響なし
Claude CodeやCursorなどにCloudflareのMCPを古い設定でつないでいると、ある日突然つながらなくなります。MCPの通信方式がSSEから新しい方式へ移っていく流れの一例で、ほかのMCPサーバーの設定も見直すきっかけになります。

Copilot、未設定の機能を既定値に

GitHubは、Copilot Business / Enterpriseで一般提供中の機能やクライアント機能について、9月に予告した「グローバル既定ポリシー」の適用を始めました。10月26日までに企業・組織ごとに順次反映され、管理者が個別に設定していない機能は、選ばれた既定値に一度だけそろえられます。

キーポイント

  • 10月22日から10月26日にかけて順次適用。組織によって反映のタイミングが違う
  • 未設定の機能だけが、既定値（有効・無効・各組織に任せる）に一度だけそろえられる
  • すでに有効・無効を明示している機能は、そのまま変わらない
  • プレビュー機能は引き続き、自分で選んだ場合だけ有効
  • 対象は「Features & clients」と「MCP servers in Copilot」の設定。AI Controls → Copilot → Default policy for new features で確認できる
組織でCopilotを管理している人は、気づかないうちに機能やMCPサーバーの利用可否が変わる可能性があります。週明けまでに既定値を確認しておくべき変更です。

〈知見〉AIの画面は説明を足しすぎない

Claude OpusとGPT-6 AstraでUIを多く作ってきた開発者のZihua氏（@luinlee）が、AIっぽい雑な画面を避けるコツとして、AGENTS.mdに一文を書き足す方法を紹介しました。書き足すのは「Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.」（不要な補助ラベルや説明文を避け、説明はレイアウトに任せる）という指示です。AIが作る画面にありがちな、見出しの下の小さな説明文や、意味の重なったラベルを減らす狙いです。

キーポイント

  • エージェントが毎回読む指示ファイル（AGENTS.md）に、方針を一文で入れておく
  • 減らす対象は、見出し下の補足説明や重複したラベルといった「足し算」の要素
  • 禁止語の一覧ではなく「説明はレイアウトに任せる」という方針で伝えている
  • コードレビューの側で、補助ラベルや説明文を避けるチェック項目を設ける方法もあわせて紹介（投稿者の自社ツールの宣伝を含む）
Claude CodeやCodexで画面を作るとき、同じ一文をAGENTS.mdやCLAUDE.mdに入れるだけで試せます。生成後のレビューでも「この補足は本当に要るか」を確かめる観点として使えます。
